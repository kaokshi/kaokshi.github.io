# Приватная передача полных черновиков из GitHub Actions

**Назначение.** Владелец попросил после теста девяти текстов присылать **полные статьи** для согласования. Публичный GitHub-репозиторий и открытые артефакты Actions не должны содержать их без шифрования. Ранее запуск сохранял только метаданные, а содержимое RAM/временной папки GitHub Runner уничтожается после исполнения. Сохранить задним числом тексты из старого запуска нельзя.

## Реализовано (пилот, не автономная доставка в чат)

- Тест `real-nine-qwen-e2e.yml` использует **открытый X25519 ключ владельца** `ZEN_REVIEW_PUBLIC_KEY_HEX`. В коде используется свежий одноразовый X25519 ключ, HKDF-SHA256 и AES-256-GCM для шифрования полного ZIP с черновиками, отчётами и статусами.
- Если появились действительные черновики, из приватного рабочего каталога создаётся только `zen-real-nine-owner-review.enc`. Незашифрованный ZIP **не выгружается** в Actions. Метаданные и есть публичный отчёт, тексты остаются внутри зашифрованного файла.
- Артефакт Actions: `nine-real-qwen-owner-review-encrypted`, хранится до 30 дней в рамках лимитов GitHub. Готовые и ещё ожидающие проверки статьи помечаются раздельно.
- **Закрытый X25519 ключ не находится в коде, GitHub Actions или артефакте.** Его нужно держать только у владельца, например в защищённой папке. Потеря ключа делает архив невосстановимым.
- Для чтения: скачать файл `.enc` из артефакта Actions, установить библиотеку `cryptography` и выполнить:

```bash
python -m pip install "cryptography>=44,<48"
python src/editorial_encrypted_review.py zen-real-nine-owner-review.enc \
  --private-key /путь/к/zen_editorial_review_private_key.pem \
  --output /путь/к/новой-приватной-папке
```

- Полученный `MANIFEST.json` содержит статусы по каждому созданному черновику; полные тексты — в `articles/*/draft.json` и, если конвейер успел сформировать, `draft.md`.

## Что не подключено

- **Прямое отправление содержимого в чат ChatGPT автоматически** GitHub Actions не поддерживает без отдельного авторизованного, приватного приёмника. Ссылка на зашифрованный артефакт и уведомление о завершении теста — не доставка расшифрованных статей.
- ChatGPT не должен заявлять об отправке полного текста, пока реально не извлечёт и не передаст его. Владелец может загрузить расшифрованный ZIP в беседу, после чего возможна редакторская проверка и согласование.
- Никакая автоматическая публикация, RSS, массовая передача данных в публичные issue/PR или открытый сайт не разрешается.

Этот способ безопасно решает **сохранность полных текстов после GitHub Actions**, но не снимает необходимость отдельного приватного транспорта для полностью автоматического вручения в ChatGPT.
