| Qwen3-4B-Instruct-2507, GGUF Q4_K_M | Apache 2.0 у исходной модели. Файл весов 2,50 ГБ. Поддержка llama.cpp и Ollama. | Основной пилот. Оценка русского текста и фактической точности опирается на результаты пилота. Qwen3 8B, Gemma и сервер Ollama не входили в сравнение на одинаковых статьях.

## Запуск CPU-исполнителя

Скачайте [CPU-сборку llama.cpp b12580](https://github.com/ggml-org/llama.cpp/releases/tag/b12580) и GGUF модели в каталог вне GitHub-репозитория. В пилоте использованы версия весов `ae44f08e1392f39c0e474af10c3ff8355c8b6688` и SHA-256 `2fde00ce69dd4899c70d020845e2638353015bba0fdf161b3eb965f2bca4464e`. Одна очередь требует 8192 токена контекста.

```sh
llama-server --host 127.0.0.1 --port 8093 --model "$GGUF" \
  --alias qwen3-4b-instruct-2507 --ctx-size 8192 --parallel 1 --threads 2 --no-ui
```

В другом терминале запустите [редакционный цикл](EDITORIAL_PIPELINE.md). Для проверки готовности используйте `GET /health` на локальном сервере.

```sh
export ZEN_LLM_BACKEND=llama.cpp
export ZEN_LLM_MODEL=qwen3-4b-instruct-2507
export ZEN_LLM_URL=http://127.0.0.1:8093
export ZEN_LLM_MODEL_REVISION=2fde00ce69dd4899c70d020845e2638353015bba0fdf161b3eb965f2bca4464e

python src/editorial_pipeline.py --channel legends --topic "$LEGEND_TOPIC" \
  --provider src/editorial_local_llm.py --output "$PRIVATE_DRAFTS"

python src/editorial_pipeline.py --channel science --topic "$SCIENCE_TOPIC" \
  --provider src/editorial_local_llm.py --europe-pmc --research-query "$PUBLIC_QUERY" \
  --output "$PRIVATE_DRAFTS"
```

Для Ollama импортируйте GGUF через `ollama create` с локальным Modelfile `FROM /path/model.gguf`. Запустите Ollama на loopback, укажите `ZEN_LLM_BACKEND=ollama`, тег в `ZEN_LLM_MODEL` и URL `http://127.0.0.1:11434`. Адаптер передаёт схему в `/api/chat`. Для llama.cpp используется `/v1/chat/completions`. [Структурированные ответы llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) · [Структурированные ответы Ollama](https://github.com/ollama/ollama/blob/main/docs/api.md)

Адаптер принимает только HTTP-адреса loopback. Выход валидируется по схеме. Есть один повтор при временной ошибке или некорректном ответе. `ZEN_LLM_TIMEOUT` задаёт ожидание одного ответа в секундах, по умолчанию 360, допустимый диапазон 30–900. При ссылках на источник модель выбирает номер прочитанного фрагмента, а адаптер восстанавливает точную цитату и URL. Редактор по-прежнему проверяет предметное соответствие. Наличие источника и решение модели записываются отдельно.

Правило объёма хранится в `config/ai_revision_policy.json`. Видимый текст статьи должен содержать от 3000 до 6000 символов без пробелов включительно. Если модель выпускает текст за пределами нормы, дело сохраняет оригинал, а цикл использует одну из тех же двух агентных правок для содержательного дополнения или сокращения. Каждая версия получает собственные проверки. Незавершённые этапы остаются видны в отчёте. `draft.md` представляет текст для чтения, `case.json` сохраняет историю, `sources.json` содержит ссылочные доказательства.

Локальный исполнитель также подключается к `editorial_learning.py --provider src/editorial_local_llm.py`. Модель получает только сводку повторяющихся подтверждённых замечаний. Предложения сравниваются на независимых примерах через `--holdout` и ждут решения владельца.

Для постоянного запуска используйте отдельный CPU-исполнитель с локальным сервером модели, постоянным кэшем весов и приватным каталогом дел. GitHub Actions проверяют код и штатные детекторы. Сервер с весами и черновиками имеет смысл держать на отдельной машине, чтобы возобновлять дела после завершения заданий CI. Настройка автоматического запуска и транспорта согласования выполняется отдельным этапом.
