# Sapling API: экспериментальное диагностическое подключение, 20.11.2026

Статус: **экспериментальная ветка, ручной запуск; НЕ публикационный шлюз**.

## Что добавлено

- `src/sapling_external_diagnostic.py`: официальный `POST https://api.sapling.ai/api/v1/aidetect`, заголовок `Authorization: Bearer`, `zero_retention:true`, `create_report:false`.
- `.github/workflows/sapling-external-diagnostic.yml`: **только workflow_dispatch**, один явно выбранный существующий slug и максимум 10 000 символов; по умолчанию 1900, чтобы воспроизвести ранее сравнивавшиеся фрагменты.
- `tests/test_sapling_external_diagnostic.py`: локальные mock-тесты, не вызывающие внешний API.
- Только SHA-256, оценки и координаты предложений хранятся в 7-дневном артефакте; исходный текст и API-ключ в отчёт не попадают. **Сам запрос передаёт текст Sapling**, поэтому отправлять только материалы, разрешённые для внешней обработки.
- Никаких запланированных запросов, обновления контента, RSS, GitHub Pages, моделей и release-статусов. Даже успешный результат не авторизует выпуск.

## Как включить опытную проверку

1. В Sapling API settings самостоятельно создать ключ и сохранить его в GitHub repository secret с именем `SAPLING_API_KEY`; **не вставлять ключ в Issue, чат, файл или лог**.
2. После просмотра и мерджа экспериментального PR вручную выбрать в GitHub Actions workflow `Sapling external diagnostic (manual, read-only)`, конкретный `slug` и размер.
3. Пока секрет не добавлен, workflow завершится без внешнего запроса; это ожидаемое поведение.
4. Бесплатный пробный ключ имеет 50 000 символов за 24 часа, 250 000 за месяц и ограниченный срок действия; условия проверять на https://sapling.ai/docs/sandbox/. По исчерпании лимита запрос должен завершиться ошибкой, **не переходить на платный план автоматически**.

Данные показывают расхождение, **не** превосходство одного классификатора. Эти три текста не образуют валидационную выборку и не являются доказанными эталонами происхождения. Нельзя подгонять веса под три оценки Sapling и затем объявлять точность улучшенной.

## Дальнейший эксперимент по улучшению собственных моделей

1. На одинаковых SHA-фрагментах собирать результаты всех четырёх действующих детекторов и отдельный ответ Sapling; логировать версию модели и язык. Тексты не сохранять в открытых артефактах.
2. На достаточно большой контрольной выборке с **независимо установленным авторством** отдельно по жанрам оценивать FPR, TPR, разрывы между классами, интервалы неопределённости и расхождения между моделями.
3. Не обучать напрямую на ответах Sapling как на «правильных» метках. Можно исследовать ошибки, но реальное качество мерить на изолированных примерах подтверждённого происхождения.
4. После исследований предложить отдельный экспериментальный вариант жанрового ансамбля, сравнить на неизменном holdout, не трогать текущую систему и её отключённые пороги.
5. Внешние проверки применять только к сомнительным или небольшой случайной контрольной доле текстов. Пока нет доказанного селектора, выбор ручной. Принцип: низкие внутренние индексы не означают низкий показатель Sapling.

Прежде чем разрешать автоматические вызовы, требуется отдельная реализация общего месячного лимита и исключения повторных запросов. Текущий предел 10 000 — **на один запуск**, а не защита месячного бюджета. Ветка не разрешает рекламу, расходы или автоматическую публикацию.
