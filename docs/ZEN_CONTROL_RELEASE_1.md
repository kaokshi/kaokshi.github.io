# ZEN CONTROL 1.0 RC2

## Ошибка развёртывания

В запуске [45446058054](https://github.com/kaokshi/kaokshi.github.io/actions/runs/45446058054) Cloudflare подтвердил новый Worker и проверки приватных API прошли. Ошибку выдала однократная проверка публичного app.js по маркерам сразу после развёртывания. Лог не сохранял статус и тело ответа, поэтому выяснить, какой маркер отсутствовал или запаздывал ли edge, по нему нельзя. При повторном чтении публичный Worker вернул HTTP 200 и JavaScript, побайтно совпадающий с развёрнутой версией. RC2 сверяет полный HTML, CSS и JavaScript, изолирует запросы проверки версией развёртывания и ограниченно ожидает сходимости. Ошибка авторизации не повторяется.

## Поток задач

Telegram подтверждает владельца и сохраняет задания и режим в Durable Object. Облачный цикл раз в 15 минут получает подтверждённые задания, записывает их в приватный CAS-реестр, обходит незаконченные статьи с устойчивым курсором и продвигает до двух этапов за цикл. Ручной режим требует команды на этап. Полуавтономный требует подтверждения границ иллюстраций и сборки. Автономный использует тот же диспетчер и те же обязательные проверки. Перед новым платным вызовом сверяются режим и его версия, аварийная остановка, бюджет, баланс и ключ операции. Уже принятый провайдером запрос нельзя отозвать. Его ответ сохраняется и подлежит сверке.

Подтверждённое задание таймера может готовиться накануне даты выпуска по МСК в пределах 24 часов. Ручные заказы с будущей датой сохраняют прежнее ограничение. Для кино новое производственное задание таймера не создаётся. Мост и Python дополнительно отклоняют этот канал. Выпуск и RSS закрыты во всех режимах.

Повтор известного временного сбоя возможен через 15 минут, максимум дважды. Принятые работы восстанавливаются из приватных контрольных точек. Для позиции изображения разрешена одна генерация и два исправления. При сохранённом ответе с тарификацией реестр восстанавливается без вызова модели. Если ответ потерян, автоматический повтор невозможен до сверки. Финансовые, правовые и серьёзные редакционные блокировки автоматически не снимаются.

## Бюджет и пилот

Основной лимит 300 ₽ и резерв 50 ₽ за московские сутки. В скользящий лимит редакции 9000 ₽ за 30 дней входит и резерв. Он применяется только к начатым статьям. У чата Qwen отдельный лимит 10 ₽ в сутки, а финансовая блокировка аккаунта общая. Параметры исполнения задаёт `config/zen_core.json`. Проверки качества и читатели исторических архивов используют отдельные модули. [Очистка RC2](LEGACY_PROVIDER_RETIREMENT.md)

Пилот подготовлен для одного нового заказа legends и одного science в ручном режиме, с одной статьёй на канал. Названия, тексты и кадры создаёт штатный маршрут. В каталоге RouterAI есть все четыре модели. Цена одного кадра Seedream — 1,92228192 ₽, маршрут Seed SG. Для семи художественных кадров мистики и до пяти научпопа смешанного формата расчёт по плановым объёмам токенов, первым генерациям и визуальным проверкам составляет **72,43 ₽**. Сценарий с повторами и дополнительными проверками — **около 175,66 ₽**. Это расчётные сценарии, фактический счёт зависит от количества этапов, размеров входов и повторов. Редакционные платные вызовы в рамках RC2 не делались. Прежний изолированный лимит 70 ₽ не менялся. Для пилота, который укладывается в 70 ₽, потребуется остановиться у лимита или согласовать иной потолок до запуска.

Для финального пакета с Seedream остаются неподтверждёнными коммерческие права на фактический маршрут. Генерация для приватного просмотра отделена от финальной проверки прав. Старые материалы эта работа не меняет. [Каталог RouterAI](https://routerai.ru/api/v1/models) · [Поставщик Seedream](https://routerai.ru/api/v1/models/bytedance-seed/seedream-5-0-flash/endpoints) · [Оферта RouterAI](https://routerai.ru/terms/).

## Активация после согласования

1. Объединить интеграционную разработку с основной веткой после успешных проверок и согласования.
2. Обновить существующий Worker в режиме приватного просмотра с проверкой ожидаемой действующей версии. Проверить точное совпадение файлов и действительную сессию владельца в Telegram. Живой Worker на RC2 в рамках этого PR не обновлялся.
3. Включить в GitHub только переменную ZEN_CORE_INTAKE_SCHEDULE_ENABLED. Проверить бесплатный проход таймера из основной ветки, курсоры, отчёты и сверку. Реестр уже существует в приватном GitHub.
4. После отдельного согласования стоимости платного пилота синхронно включить частное исполнение через binding Worker ZEN_CORE_EXECUTION_ENABLED, переменную Actions ZEN_CORE_PRODUCTION_ENABLED и config/zen_core.json:execution_enabled. Проверить первую ручную стадию для каждого активного канала. Нужны действующие ключи RouterAI, приватного хранилища и общий секрет моста.
5. Реальный выпуск, промышленный тест таймера и Telegram-сессия владельца требуют отдельных проверок. Существующий GitHub Pages и три RSS-адреса сохранены. Активация публикации и RSS требует отдельного разрешения.

Офлайн-тесты проверяют реальные переходы состояния с синтетическим транспортом. Они не подтверждают состоявшиеся вызовы платной цепочки.
