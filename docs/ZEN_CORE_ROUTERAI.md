# Интерфейс ZEN CORE для RouterAI

Контракт с версией `zen-core/v1` принимает сохранённое задание ZEN CORE с полями `id`, `plan.items`, `plan.day`, `plan.instructions` и необязательным `releaseAt`. Он проверяет каналы и число статей, сохраняет дату и время намерения и разворачивает заказ в позиции статей. Доступные каналы на текущем маршруте — мистика и научпоп. Расписание Cloudflare и ветка Telegram CONTROL управляются отдельно.

Использовать доверенный файл задания и закрытый постоянный диск, доступный процессу исполнения. На одном хосте реестр запросов должен быть общим для всех работников маршрута. Сохранять SQLite на эфемерном диске CI нельзя. Режим приёмки, без вызовов моделей:

```sh
python -m src.editorial_zen_core --db /private/zen-core.sqlite submit /private/intent.json
python -m src.editorial_zen_core --db /private/zen-core.sqlite snapshot
```

Запись результата стадии выполняет доверенный исполнитель через `Core.stage_result`. Завершённые стадии и одобренные позиции изображений сохраняют результат. Перед платным действием исполнитель вызывает `Core.reserve_call` с уникальным идентификатором запроса, стадией, причиной и верхней оценкой. После ответа он фиксирует точную сумму через `Core.settle`. Неопределённая стоимость остаётся открытой бронью и блокирует следующие запросы, в том числе после перевода даты. Только после ручной сверки эту бронь можно закрыть известной суммой в пределах оценки. Превышение оценки требует отдельного разбора.

Лимит маршрута — 300 ₽ основного бюджета и 50 ₽ дополнительно за сутки по Europe/Moscow, как у планировщика. Новый план и черновик оплачиваются только из основного бюджета. Сверх него допускаются недостающий кадр, его исправление, обязательная проверка, требуемая правка и завершение статьи с уже принятым черновиком. Один кадр имеет до трёх платных попыток. Принятый кадр повторно не резервируется. Изолированный тест PR №85 сохраняет собственный лимит 70 ₽ и прежнюю отчётность.

ZEN CONTROL получает снимок через доверенный транспорт. Поля `budget.mainDailyRub`, `budget.mainRemainingRub`, `budget.reserveDailyRub`, `budget.reserveRemainingRub`, `budget.reserveUses`, `budget.unsettledRequest` содержат лимиты, остатки и причину каждой брони резерва. В `jobs` содержатся число статей, даты, расходы, стадии и статусы проверок. Денежные значения передаются десятичными строками. Снимок исключает указания владельца, тексты статей и секреты. Передача в уже развернутый Worker, общий постоянный диск и обвязка живых вызовов остаются задачами интеграции. Публикация, RSS и автоматическое исполнение выключены.

Повременные и общие лимиты действуют для запросов, зарезервированных в этом реестре. Старые отчёты RouterAI остаются источником исторических расходов и автоматически не начисляются на новый день. Ветки с устаревшими рабочими процессами и проверками качества сохраняют совместимость.
