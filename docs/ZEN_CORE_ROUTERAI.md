# Контракт исполнителя ZEN CORE / RouterAI

Исполнитель принимает сохранённое задание ZEN CORE с полями `id`, `plan.items` (канал и число статей), `plan.day`, `plan.instructions`, необязательным `releaseAt` и полем `mode`. Допустимы мистика и научпоп, всего до девяти статей на задание. День исполнения проверяется по Europe/Moscow. `releaseAt` сохраняется как метаданные и не запускает выпуск. Транспорт управления должен аутентифицировать владельца до передачи команд исполнителю.

| Режим | Переходы |
|---|---|
| `manual` (по умолчанию) | Явная команда на единственный следующий этап |
| `semi_autonomous` | Автоматические переходы до границ `images` и `package`. Для каждой границы требуется сохранённое подтверждение владельца |
| `autonomous` | Переходы по готовности, до блокера качества, денег либо приватного пакета |

Команды на доверенном хосте. Используются Python 3.12, `requirements-production.txt`, CPU Torch и зависимости проверок из действующего производственного окружения. Секрет `EDITORIAL_PRIVATE_TOKEN` имеет доступ к конкретному приватному репозиторию, `ROUTERAI_API_KEY` выделен этому исполнителю.

```sh
python -m src.editorial_zen_executor init
python -m src.editorial_zen_executor submit /private/intent.json
python -m src.editorial_zen_executor snapshot
python -m src.editorial_zen_executor approve order/legends/1 --stage images
python -m src.editorial_zen_executor advance order/legends/1 --stage plan
```

`advance` блокируется до любых вызовов моделей, пока `config/zen_core.json:execution_enabled` выключен. PR оставляет его выключенным, расписание запуска не добавлено. Для перехода в любой автоматический режим требуется доверенный вызов `advance` для подлежащей исполнению статьи. Контракт не включает публикацию и RSS, даже при автономном режиме. ZEN CONTROL 1.0 RC2 управляет интерфейсом и транспортом подтверждённых заданий. [Описание управления](ZEN_CONTROL_RELEASE_1.md)

## Хранение и деньги

В приватном `kaokshi/zen-editorial-review` хранится `zen-core/v1/ledger.sqlite` с заказами, подтверждениями, статусами, принятыми позициями, индексами повторов и общим журналом расходов. Обновления реестра сверяют SHA предыдущего Git-объекта. Конфликт переигрывает только локальную транзакцию. Готовые материалы и ответы RouterAI сохраняются как неизменяемые файлы отдельно от реестра. Перед каждым чтением и записью проверяется приватность репозитория, проверяются пути, размер и хеш файлов. Состояние прочитано и записано в реальном приватном облаке без заданий и расходов.

Перед платным запросом атомарно фиксируется бронь по стабильному ключу «статья + операция». При возобновлении сохранённый ответ с совпадающим хешем входа используется повторно. Завершённый кадр восстанавливается по хешу из приватного файла. Если ответ потерян после отправки, автоматического повтора нет. Запрос удерживает бронь и блокирует дальнейшую оплату даже после полуночи. Если ответ сохранён, но реестр не обновился, повторно запускается только расчёт. При неизвестном результате оператор может использовать `reconcile /private/provider-invoice.json` с `requestId` и `actualRub`, подкреплёнными квитанцией провайдера. Команда сохраняет подтверждение. Она не восстанавливает потерянное тело результата и не разрешает второй вызов под тем же ключом. Для таких случаев нужна эскалация. Исторические материалы PR №85 не переносятся в новый реестр автоматически.

Основной лимит **300 ₽**, резерв **50 ₽** на московский день брони. Новые планы и черновики не тратят резерв. Сверх основного лимита доступны недостающие изображения, исправления и обязательные проверки начатой статьи. Один слот имеет максимум три платных попытки. Ранее принятый слот не генерируется снова. Стоимость берётся из учёта RouterAI. При неизвестной или превышенной оценке новые списания блокируются. Локальный лимит не ограничивает уже отправленный запрос у поставщика. Для его соблюдения другими путями тот же ключ нельзя использовать вне общего реестра. Изолированный тест сохраняет самостоятельный лимит 70 ₽.

`snapshot` возвращает существующий формат `zen-core/v1` с `budget.mainDailyRub`, `mainRemainingRub`, `reserveDailyRub`, `reserveRemainingRub`, `reserveUses`, `unsettledRequest`, `overrun` и состоянием задач. Расходы передаются десятичными строками. Снимок не содержит текстов, инструкций или ключей. Контракт RC2 передаёт снимок через очередь и квитанции. Фактическое исполнение и расписание зависят от разрешений среды.

## Проверки и права

Qwen планирует и проверяет, Claude пишет, DeepSeek редактирует, Seedream создаёт нужные художественные кадры. Используются существующие структурные проверки, морфология, LanguageTool, четыре текстовых детектора и диагностический флаг Model A, первичные источники и проверка цитат, поиск близких тем и текстов, CLIP, SigLIP, Florence-2, визуальная проверка Qwen, проверка SHA/pHash и близких композиций, Wikimedia с проверенной лицензией, научные схемы и контроль Dzen-разметки. Инструменты сторонних экспериментальных сравнений сохраняются в их диагностических маршрутах. Неполная обязательная проверка блокирует сборку.

Каталог RouterAI на дату проверки возвращает единственный маршрут Seed, тег `seed`, страна SG. Оферта RouterAI не предоставляет прав на результаты от своего имени. Применимая коммерческая лицензия именно на этот маршрут публично не установлена. Для генерации и восстановления кадра документы о правах не требуются. Перед новым платным запросом исполнитель проверяет маршрут. Сгенерированный кадр сохраняется с исходным статусом проверки прав. На финальном этапе отсутствие подтверждения отображается как отдельный блокер прав. Для подтверждения на этом этапе используются `rights/seedream.json` и документ `rights/seedream-commercial-evidence`, привязанный по SHA-256. [Оферта RouterAI](https://routerai.ru/terms/) · [Маршрут API](https://routerai.ru/api/v1/models/bytedance-seed/seedream-5-0-flash/endpoints)

Офлайн-тесты подставляют транспорт и проверяют конкуренцию обновлений, сбой до получения ответа, восстановление после сохранения ответа, сохранность принятых кадров, режимы, бюджет и права. Платное сквозное исполнение в этой работе не запускалось.
