# Резерв времени для девяти черновиков

Последняя проверка реальной Qwen3-4B на CPU показала приблизительно 4–5 минут на одну попытку генерации **без** проверки фактов, иллюстраций, Model A и редакторских исправлений. Мистическая статья в первом испытании была отклонена по структуре, поэтому полного ежедневного цикла пока нет.

Очередь `src/editorial_nine_draft_queue.py` теперь принимает дополнительный **необязательный** параметр `--deadline` в ISO 8601 с явной временной зоной и `--review-reserve-minutes` (по умолчанию 20). Например:

```bash
python src/editorial_nine_draft_queue.py \
  --plan "$HOME/.local/share/zen-editorial-private/nine-topics-2026-11-21.json" \
  --workspace "$HOME/.local/share/zen-editorial-private" \
  --deadline "2026-11-21T11:00:00+03:00" \
  --review-reserve-minutes 20
```

**Предназначение:** не стартовать новые большие задания после того, как пришло время готовить материалы владельцу. Это не общий тайм-аут: одно уже начатое задание может занять значительное время. Отложенные задания получают причину `review_deadline_reached`, а не ложный статус `ready`. Если нужен буфер больше 20 минут для экспорта DOCX и проверки иллюстраций, его следует увеличить после измерения реального времени.

Пока сквозная автономная генерация девяти статей за 08:00–11:00 МСК не подтверждена, целесообразно заранее генерировать черновики, затем проверять и передавать на согласование. Это **рекомендация, а не изменение расписания существующих автоматизаций**.

Все три канала активны для подготовки, Model A >85 — рекомендательный ориентир, RSS/публикация не включаются.
