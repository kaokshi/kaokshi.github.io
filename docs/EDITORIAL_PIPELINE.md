# Автор, смысловая редактура и фактчек Дзена

Цикл использует историю версий, повторные проверки и лимиты редактур из [первого этапа](EDITORIAL_AGENT_V1_MODEL_A_20261120.md). Каналы для подготовки черновиков — «Легенды тёмных улиц» и «За гранью очевидного».

## Один вызов

Используйте Linux и зависимости редакционных проверок из первого этапа. Укажите постоянный приватный каталог вне репозитория. Для повторного запуска указывайте тот же каталог и исходную тему или JSON. По нормализованной теме или slug открывается ранее сохранённое дело, включая использованные попытки.

```sh
python src/editorial_pipeline.py --channel science --topic "Как движутся камни на Рейстрек-Плайя" \
  --provider /absolute/path/to/local-model-adapter --europe-pmc --output "$PRIVATE_DRAFTS"

python src/editorial_pipeline.py --channel legends --article "$ORIGINAL_JSON" \
  --review "$OPERATOR_REVIEW" --output "$PRIVATE_DRAFTS"
```

Для подготовки одного текста доступен `src/editorial_writer.py --channel ... --topic ... --provider ... --output ...`. Автор проверяет диапазон 3000–6000 символов без пробелов, русский текст, наличие призыва подписаться, дубли заголовков и абзацев. Единый цикл также сравнивает текст и заголовок с корпусом и новыми черновиками в том же каталоге. Сравнение выявляет сходство в редакционном корпусе. Самостоятельность сюжета и естественность языка оцениваются при смысловой проверке.

Для каждого дела используется отдельная папка.

- `case.json` с оригиналом, каждой версией, SHA-256, редакционными причинами, промежуточными этапами и результатами проверок.
- `draft.json` и `draft.md` с текущим кандидатом или последней проверенной версией при сбое или обнаруженном ухудшении. `reports.json` связывает черновик с версией и показывает текущее решение.
- `sources.json` с выводами по утверждениям, ссылками и проверенными цитатами, если они доступны.
- `writer-status.json` с результатом создания новой статьи. Ответ автора сохраняется в приватный `writer-response.json` до проверки и может быть повторно использован после прерывания.

Редактор сначала выделяет проверяемые замечания, затем отдельным запросом предлагает конкретные изменения. Правки ограничены указанными абзацами, проверяются по исходному тексту и сохраняют остальную разметку. После правки цикл повторяет смысловой разбор, фактчек, LanguageTool, Vale, проверку ссылок, структуры, внутреннего сходства, иллюстраций и четыре детектора. Model A вычисляет среднее трёх классификаторов. При индексе строго больше 80 отчёт помечает материал для редакционного разбора. Баллы детекторов не передаются исполнителю правок.

В общей истории допускается до двух агентных редактур, включая оставшиеся механические правила, и одна правка ChatGPT. `assistant_handoff_pending` означает готовый пакет; после переноса оператором можно передать ответ через `--assistant-response` в формате первого этапа. `owner_review_pending` означает материал на согласование и перечень открытых замечаний. `checks_pending`, `semantic_review_pending` и `fact_check_pending` указывают на отсутствующие результаты. Фактчек по выборке утверждений, наличие иллюстраций и права на них оцениваются отдельно при согласовании.

## Подключение исполнителей

Встроенный адаптер работает с локальным llama.cpp или Ollama. Порядок запуска приведён в [инструкции локального исполнителя](EDITORIAL_LOCAL_LLM.md).

`--provider` указывает на локальный исполняемый адаптер уже выбранной языковой модели. Он получает один JSON на stdin и возвращает один JSON на stdout. Обработка ошибок и таймаут встроены. Без адаптера автор сообщает `provider_not_configured`. Для научной статьи прочитанные документы можно подать до генерации. При недостающем или избыточном объёме цикл пытается исправить текст в пределах действующего общего лимита.

| Задание `task` | Вход адаптера | Поля ответа |
| --- | --- | --- |
| `write` | Канал, тема, существующие заголовки и инструкция жанра | `title`, `paragraphs` и `cta` |
| `diagnose` | Заголовок, канал, хеш и пронумерованные абзацы | `issues`, каждый с `id`, `category`, `paragraph`, точной `quote`, `reason` |
| `revise` | Те же абзацы и подтверждённые замечания для текущего хеша | `edits`, каждый с `issue_id`, `paragraph`, полным `before`, `after`, `reason`. Для удаления диагностированного пустого абзаца передайте `remove: true` и пустой `after` |
| `extract_claims` | Заголовок и абзацы научной статьи | `claims` с `id`, `paragraph`, точной `quote`; необязательный английский `search_query` |
| `compare_claims` | Утверждения и прочитанные документы | `verdicts` с `id`, `verdict`, `reason`, `evidence` из объектов `url` и точной `quote` |

Категории редакторских замечаний — `logic`, `opening`, `filler`, `natural_language`, `chronology`, `unsupported_claim`. При `--review` оператор может подать эти же результаты массивом объектов по одному на `text_sha256`. В каждый объект входят `issues` и `edits`, а для научпопа также `claims` и `verdicts` при наличии прочитанных источников. Нумерация охватывает простые абзацы без вложенной разметки и цитатных блоков.

`--europe-pmc` выполняет явный поиск по открытым аннотациям. Для других тем и полнотекстового чтения используйте `--research-provider`. Его задание `discover` получает тему, поисковый запрос и утверждения, а ответ содержит `documents` с `url`, `title`, `kind` (`primary` или `secondary`) и фактически прочитанным `text`. Через `--source-documents` можно передать тот же объект вручную. Каждая оценка `confirmed` или `disputed` требует точной цитаты из предоставленного первоисточника. `unconfirmed` оставляет вопрос открытым. Доступность ссылки, полнота списка утверждений и смысловое соответствие цитаты — отдельные вопросы. В отчёте отмечаются происхождение заключения и объём источника, доступный проверке.

## Предложения и независимая оценка

Версии нового цикла совместимы с существующим вводом `editorial_learning.py --review CASE OWNER_FEEDBACK`. Категория `opening` дополняет уже поддерживаемые категории. Подтверждённые отзывы группируются по жанрам и используются для предложений.

Флаг `--holdout FILE` сравнивает результаты эксперимента с текущими инструкциями. Файл `zen-editorial-holdout-v1` содержит `reviewer: "owner"`, `blinded: true`, `experiment` и `samples`. Каждая запись содержит `slug`, `channel`, `baseline` и `candidate` с `text_sha256` и объектом `defects` с количествами по `facts`, `language`, `originality` и `story_logic`. Проверка отклоняет повторы и пересечения с переданными случаями обучения. Для независимости владелец заранее отделяет контрольные материалы от всех использованных при разработке и сравнивает версии вслепую. Отчёт показывает изменения по жанрам и отдельным видам ошибок. Внедрение промптов и моделей требует одобрения владельца.

В обеих статьях цикл применил адресные правки по операторской разметке, повторил штатные проверки и сохранил отдельные хеши. Смысловой пилот не использовал mock-ответы. Подключение локальной LLM и автоматического транспорта остаётся отдельным этапом. Полный текст, пакеты и черновики хранятся вне публичного репозитория.
