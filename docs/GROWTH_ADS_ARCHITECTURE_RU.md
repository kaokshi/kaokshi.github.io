# Архитектура продвижения трёх каналов Дзена
Дата: 2026-11-19. Режим: полуавтоматический; расходы и кампании — **только после одобрения владельцем**.

## Цели и ограничения
- Направления: `cinema` — «Кадр за Кадром» (существует, 11 подписчиков на 2026-11-19); `legends` — «Легенды тёмных улиц» и `science` — «За гранью очевидного» (пока не созданы).
- Публикация статей и привязка RSS в Дзен остаются выключенными до отдельной команды. Глобальный `publication_enabled=false` не менять.
- Никакого автоматического списания рекламных средств и отправки изменений в рекламный кабинет без явного подтверждения.
- Бюджет на разработку: 0 ₽ за программную основу при использовании существующего GitHub Pages и локальных инструментов; рекламные расходы согласовываются отдельно. API может потребовать доступ и проверки со стороны VK.

## Схема
1. **Студия Дзена:** органические показы, открытия, дочитывания, подписчики и динамика отдельных статей. Доступ к официальному публичному API статистики каналов не подтверждён. Сначала экспорт/ручная выгрузка (при наличии), затем изучение разрешённых интеграций. Никаких нестабильных схем входа по паролю и обхода ограничений.
2. **VK Реклама:** отдельные метрики платных кампаний: расходы, показы, клики, дочитывания и подписки согласно выбранным целям. Интеграция через официальный API после получения разрешения и OAuth-доступа; иначе разрешённые выгрузки CSV.
3. **Яндекс Метрика:** отдельный счётчик для `kaokshi.github.io` после создания счётчика владельцем. Отслеживание посещений сайта, источников и целей; **это не заменяет статистику Дзена**.
4. **Локальный слой обработки:** нормализация CSV в единую схему (см. `growth/README.md`), расчёт CTR, доли дочитываний, стоимости целевого действия; отчёты по каналам и публикациям. Исходные данные не загружать в публичный GitHub-репозиторий.
5. **Редакторский блок:** список гипотез — новые темы, названия, обложки, содержание. Держать логику решения отдельно от генерации и публикации материалов.
6. **Рекламные черновики:** текст объявления, объект продвижения, аудитория, цель, период, max spend, гипотеза, прогноз и критерий остановки. Черновик оформляется для согласования в чате.
7. **Ручной шлюз согласования:** только после подтверждения владельца подготовить изменения и выполнить их через выданный доступ; подтверждение на одну кампанию не разрешает будущие действия.
8. **Аудит:** журнал предложений и согласований, кто одобрил, какие суммы, идентификаторы VK-кампаний, старые/новые настройки, время применения.

## Изоляция и безопасность
- Текущий сайт и его исходный репозиторий **публичные**. В него можно размещать только код, пустые шаблоны и общие справочные документы. Не хранить в нём реальные данные кабинетов, клиентские идентификаторы, токены, скриншоты приватной аналитики, персональные данные.
- Для действующей интеграции создать **отдельный приватный репозиторий** или другое защищённое хранилище (после согласования); credentials хранить в секретах Actions или секретном менеджере, минимально необходимые права; расходы менять только через ручной approval. Не передавать пароли/секреты в чат.
- Публичный GitHub Pages нужен для сайта, но не для внутренних отчётов. Нельзя размещать внутренний дашборд там, где его смогут открыть все.
- Настраиваемая защита: max budget на кампанию и на сутки; default OFF для любых операций create/update/pause; dry-run сначала; реальная запись только после отдельной команды.
- Сравнивать органику Дзена и платные результаты VK раздельно: суммирование охватов разных источников без проверки определения метрик может искажать выводы.

## Дорожная карта
**Этап 0 (сейчас, 0 ₽):** согласовать метрики, цели, лимиты; собрать шаблон CSV и локальный скрипт расчётов; подготовить отчётные форматы, не подключая кабинеты.
**Этап 1 (после создания каналов, 0 ₽):** связать каждый канал с общим рекламным кабинетом VK Рекламы средствами Студии (функции и ограничения проверить на месте); создать и установить счётчик Яндекс Метрики на сайт. Получить первые реальные данные из Студии.
**Этап 2 (после разрешения владельца):** запросить API VK Рекламы в кабинете, настроить read-only для статистики или CSV; сделать приватное хранилище данных и автоматические отчёты. При отсутствии API — ручной импорт экспорта.
**Этап 3 (после проверки органики):** подготовить 2–3 гипотезы и рекламные креативы, выбрать **одну** кампанию для малобюджетного теста с фиксированным лимитом и датой остановки. Минимальный бюджет определяется кабинетом VK; предлагаем ориентир 1 500–3 000 ₽ на пилот, но не запускаем без отдельного утверждения. При недостаточных данных не масштабируем.
**Этап 4:** сравнить платные подписки и дочитывания с затратами, обновить контент-план и сделать еженедельный отчёт: победители, риски, что предлагается изменить, сколько это стоит.
**Этап 5:** только при надёжной интеграции расширить автоматизацию до создания *остановленных* рекламных черновиков; активация и расходы остаются за владельцем.

## Точные определения метрик
- CTR Дзена = органические открытия / органические показы * 100%, если обе метрики представлены на одном уровне и за один период.
- Доля дочитываний = органические дочитывания / органические открытия * 100%, если определения совместимы.
- CPI/CPSubscribe VK = расходы на кампанию / **атрибутированные платные** подписки. Если платные подписки не доступны или равны нулю, метрика неопределена, а не 0 ₽.
- CPRead VK = рекламные расходы / атрибутированные рекламные дочитывания при наличии данных.
- Не выдавать прогнозы дохода за гарантированные результаты. Не считать подписчиков Дзена, приросших за период, всецело результатом рекламы.
- Нельзя выводить эффективность из одного низкообъёмного дня. Для решения об остановке смотреть на достаточность выборки, цели кампании и траты относительно заранее утверждённого лимита.
