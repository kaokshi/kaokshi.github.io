# Редакционный конвейер GitHub: доработка → проверка → следующий этап

**Статус 20.11.2026: экспериментальный PR, только чтение, без публикации.**

Самое полезное средство здесь — **GitHub Actions** (оркестрация и повторные запуски), **GitHub Checks / Job Summary** (видимый вердикт), аннотации к файлам (конкретные замечания) и **Pull Request** (хранение редакций и их обсуждение). Это не новый детектор, не внешняя проверка текстов и не попытка «обмануть» Дзен.

## Четыре маршрута

| Исход | Что делает редакция |
| --- | --- |
| `needs_revision` | Вернуть автору конкретные содержательные/технические замечания. После правки запустить все проверки заново |
| `awaiting_evidence` | Выполнить отсутствующую или устаревшую проверку в GitHub. **Не путать её отсутствие с ошибкой текста** |
| `needs_editor_review` | Передать редактору вопросы фактов, прав, противоречий или оригинальности — здесь нельзя без доказательств записать completed |
| `ready_for_next_stage` | Перейти к предпросмотру для владельца. **Не публиковать; не добавлять RSS** |
| `paused` | Кино сохраняется как будущий канал; производство не запускать |

Правило принятия решения для нового редакционного этапа: известные неисправности текста/иллюстраций → конкретная доработка; иначе незавершённая проверка → ожидание; иначе открытый редакторский вопрос → редактор; иначе следующий этап. Один и тот же материал не считается прошедшим, если изменился его текст, сведения об источниках или байты иллюстраций: SHA-256 текущего состояния сравнивается с каждым отчётом.

**ИИ-детекторы:** только ruBERT v4, ModernBERT, LightGBM, AI Accent Detector, встроенные в GitHub. RuBERT **без жёсткого порога 25%**; неподтверждённые проценты *не запускают обязательную переработку* и не становятся «вероятностью ИИ». Пока не проверен независимый порог, отчёт — диагностический. Явные проблемы стиля и содержания при этом можно направить на исправление через проверки качества.

## Точные входные данные

`src/editorial_stage_gate.py --slug legends-example` читает:

- `content/articles/<slug>.json` — полный источник статьи и 7–8 иллюстраций;
- `editorial-check-reports/<slug>.json` — реальный отчёт всех четырёх GitHub AI-инструментов с `article_slug`, `article_sha256`, `all_checks_completed:true`, `checks[tool].status:completed`. На экспериментальной ветке генератор `src/editorial_ai_check.py` добавляет отпечаток исходного текста и изображений;
- `editorial-stage-evidence/<slug>.json` — редакционные доказательства с совпадающим `article_sha256`, реальной ссылкой `report_ref`, `status:completed` и `checks` по 7 независимым шагам: `grammar`, `style`, `sources`, `image_similarity`, `image_rights`, `fact_check`, `rss_dry_run`. Каждый шаг должен быть реально выполнен; статусы `completed`, `failed` + описательные `findings`, либо `needs_review`. Для мистики требуется `fiction_originality_reviewed:true`; для научпопа все `verified_claim_ids` должны соответствовать фактическим `claims[].id`.

Пример **ТОЛЬКО СТРУКТУРЫ**, не результат успешной проверки:

```json
{
  "status": "INCOMPLETE_UNTIL_ACTUAL_CHECKS_RUN",
  "article_sha256": "<SHA256_ТЕКУЩЕЙ_СТАТЬИ_И_ИЗОБРАЖЕНИЙ>",
  "report_ref": "<REAL_GITHUB_RUN_URL>",
  "checks": {
    "grammar": {"status": "needs_review"},
    "style": {"status": "needs_review"},
    "sources": {"status": "needs_review"},
    "image_similarity": {"status": "needs_review"},
    "image_rights": {"status": "needs_review"},
    "fact_check": {"status": "needs_review"},
    "rss_dry_run": {"status": "needs_review"}
  }
}
```

**Не заполнять `completed` вручную ради зелёного статуса.** Часть шагов пока не соединена с единым архивом подлинных результатов, поэтому переход от прохождения отдельных GitHub Actions к полному автоматическому `ready_for_next_stage` ещё необходимо интегрировать и проверить end-to-end. Это блокер для самостоятельной публикации, но не для редакционного вывода конкретных замечаний.

## Команды и проверка

```bash
python -m unittest tests.test_editorial_stage_gate -v
python src/editorial_stage_gate.py --slug legends-01-prohodnaya-17
```

Результат сохраняется в `editorial-stage-results/<slug>.json`, а ручной запуск workflow `.github/workflows/editorial-stage-gate.yml` также показывает Job Summary и аннотации к тексту в GitHub Actions. Непройденная проверка не меняет статус статьи и ничего не отправляет в RSS. Синтетические unit-тесты проверяют переходы состояний, **не** являются подтверждением прав, фактов или прохождения реального ИИ-детектирования.

## Следующие технические интеграции

Связать существующие рабочие workflow `editorial-ai-checks.yml` и `editorial-quality.yml` в одну автоматическую проверку данного коммита с передачей реальных артефактов (например, `actions/upload-artifact` / `download-artifact`). Сделать унифицированные машинно-читаемые исходы LanguageTool, Vale, проверок URL, изображений, авторских прав и фактов; невозможно «отметить completed» без ссылки на успешный запуск и конкретный неизменный digest. Затем автоматически назначать задачу на редактуру с точными замечаниями и контролировать повторные попытки (предельное число, циклы, новые версии). Прежняя система RSS в данном эксперименте не используется.

Все экспериментальные функции — в отдельной ветке, **не сливать в main до настоящего интеграционного теста**. Активны `legends` и `science`, кино лишь на паузе.


## Проверенный запуск полного редакционного этапа 20.11.2026

[GitHub Actions #44707681069](https://github.com/kaokshi/kaokshi.github.io/actions/runs/44707681069): **реальный успешный сквозной тест** на черновике `legends-01-prohodnaya-17`. Четыре существующих AI-детектора выполнены, штатная проверка `editorial_quality.py`, LanguageTool (0 подсказок), Vale и техническая сборка 3 RSS без публикации (все три ленты имели 0 элементов). `src/editorial_collect_receipts.py` создал привязанный к текущему digest пакет: grammar/style/rss_dry_run = `completed`, sources/image_similarity/image_rights/fact_check = `needs_review`. Маршрутизатор вернул `needs_revision`: **добавить изображения до 7+**, отдельно запросить проверку прав, фактов и оригинальности. Ни один показатель ИИ не послужил причиной переписывания.

Теперь на **PR, меняющем одну статью**, job `routing-regressions` определяет её slug, `full-first-party-pilot` запускает установленные на GitHub редакционные инструменты, архивирует реальные отчёты, `route-changed-pr-articles` скачивает **их же** из артефакта этого запуска и выводит замечания в GitHub Checks. Если статья не прошла, PR получит красную проверку и перечень доработок/недостающих подтверждений. Следующее изменение статьи снова запускает проверку и инвалидирует прежние digest. Если все обязательные результаты документированы, маршрут `ready_for_next_stage` переводит к предпросмотру владельцу, но не к публикации. Для одной статьи — один PR, чтобы избежать пропущенных материалов. Если PR касается только кода, дорогие модельные проверки пропускаются.

**Ограничения реального запуска:** набор доказательств пока содержит `needs_review` для прав, научных фактов, источников и неохваченных типов визуальной схожести; автоматическое подтверждение этих пунктов без доказательств запрещено. Ещё **нет** автономного генератора исправленной статьи, который сам перепишет текст после замечания. В текущей реализации GitHub направляет задачу автору через блокирующий PR Check и список исправлений; редактирование делает автор/редакционный ассистент, затем запускает повторную проверку. Это **не** конечная автоматизация всей редакции и тем более не разрешение на RSS/Дзен.


## Автоматическая передача прошедшего материала на следующий шаг

`src/editorial_stage_preview.py` создаёт **только после `ready_for_next_stage`** локальный предпросмотр `editorial-stage-results/owner-preview/<slug>/index.html` с текстом и копиями утверждённых иллюстраций. В HTML экранируется текст, запрещены скрипты, а изображения разрешены исключительно из `content/assets/`. Изменение текста или байтов иллюстраций аннулирует одобрение предыдущего этапа и предотвращает создание предпросмотра. Из GitHub Actions файл загружается только как диагностический артефакт, никогда в `site/` и не в RSS.

Для новых PR с **одним изменённым материалом** весь набор установленных проверок GitHub автоматически проверяет именно его. `route-changed-pr-articles` использует артефакты этого **же** run, выдаёт блокирующий Check и аннотации до исправления; после исправления новой версией PR весь цикл повторяется. Сценарий без изменённой статьи ограничивается тестами кода и не тратит ресурсы на повторный запуск четырёх ИИ-моделей. В ручном `workflow_dispatch` можно передать slug конкретного черновика.

**Пока остаются ручными** подтверждение права использования изображений, существенных фактов/научных выводов, вычитка спорных подсказок и финальное решение владельца. Это сознательные ограничения, а не «успешные автоматические тесты». Также нет автоматического переписывания статьи силами самого GitHub: он создаёт точную задачу автору/редактору, но не подменяет источник текста. Ни один этап не вызывает существующую публикацию.
