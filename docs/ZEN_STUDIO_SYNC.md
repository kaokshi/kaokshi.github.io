# Нативная статистика Дзена в ZEN CONTROL

Вкладка «Статистика» открывается после проверки подписи Telegram Mini App владельца. В ней видны период каждого XLSX-отчёта, показатели Дзена, последние 12 разных снимков на канал, время последнего успешного сбора всех трёх каналов, состояние входа, ошибки и доступное время Cloudflare. История строится по точным периодам отчётов; перекрывающиеся периоды не суммируются. Яндекс Метрика и проверенные отчёты Студии имеют разные источники и хранилища.

## Развёртывание и первый вход

1. После проверки PR разверните существующий Worker по штатному сценарию. Задайте `ZEN_STUDIO_WORKER_URL` (точный адрес рабочего экземпляра), `DZEN_SCIENCE_STATS_URL`, `DZEN_LEGENDS_STATS_URL` и `DZEN_CINEMA_STATS_URL` в настройках репозитория. Используйте три разных подтверждённых маршрута страницы статистики. Сбор на этой стадии выключен.
2. Сгенерируйте разные случайные 32-байтные ключи для `ZEN_STUDIO_ENROLL_SECRET`, `ZEN_STUDIO_BRIDGE_SECRET` и `ZEN_STUDIO_VAULT_KEY`. Секреты моста и регистрации передаются Worker штатным развёртыванием. Ключ шифрования доступен только доверенному терминалу владельца и задаче сбора как GitHub Actions Secret. Для кнопки «Обновить статистику» установите Worker-секрет `ZEN_STUDIO_DISPATCH_TOKEN` с правом записи Actions в этом репозитории. Держите флаг `ZEN_STUDIO_SYNC_ENABLED` выключенным до приёмки всех каналов.
3. На доверенном Linux-компьютере с доступным Chromium и зашифрованным swap либо отключённым swap запустите `node scripts/zen_studio_enroll.mjs enroll` из корня репозитория. Установите `playwright-core@1.56.1` в доступный Node.js каталог. Укажите путь к Chromium через `ZEN_STUDIO_CHROMIUM`, а адрес Worker, маршрут science и ключи регистрации и шифрования передайте через защищённое окружение. Открывшееся окно Chromium использует временный профиль в `/dev/shm`. Владелец лично входит в Дзен и открывает статистику science, затем возвращается в терминал и нажимает Enter. Команда отправляет только конверт AES-256-GCM в закрытый Durable Object. Ключ шифрования отделён от конверта. Штатный выход закрывает Chromium и удаляет временный профиль. Пароли, коды, cookies и экспорт профиля в чат или GitHub не передаются.
4. Подтвердите у обычного элемента интерфейса экспорта точное доступное имя `DZEN_STUDIO_EXPORT_LABEL` и путь ответа XLSX на том же домене `DZEN_STUDIO_EXPORT_PATH`. В конфигурацию входит только путь без query и токенов. Автомат открывает соответствующий официальный элемент интерфейса. Другой домен, неоднозначный элемент и несовместимый формат требуют проверки приёмки.
5. Включите `ZEN_STUDIO_NATIVE_ACCEPTANCE_ENABLED` и запустите workflow `ZEN Studio statistics` вручную в режиме `science`. После успешной проверки запустите `all`. Имя канала, идентификатор канала, период, структура листов и числовые показатели проверяются XLSX-импортёром. Если выгрузка не содержит доказуемого идентификатора канала, импорт останавливается.
6. После подтверждения всех трёх каналов включите `ZEN_STUDIO_SYNC_ENABLED` в Actions и Worker. Workflow запускается ежечасно на 23-й минуте UTC. Кнопка Mini App ставит ту же защищённую задачу в очередь. Поставленная в очередь задача ещё раз проверяет актуальный лимит непосредственно перед выделением браузера.

Для немедленного отзыва используется та же локальная команда с аргументом `revoke`; накопленные снимки остаются доступны. Новый вход сбрасывает приёмку каналов для нового состояния. Видимый запрос входа или истечение сохранённых cookies останавливает сбор и вызывает одно уведомление Telegram на версию сессии. CAPTCHA или другой барьер останавливает проход и отражается в статусе. Состояние разбирательства с неподтверждённым закрытием требует сверки владельцем в Cloudflare до новых запусков.

## Хранилище и лимиты

- Используется отдельный экземпляр Durable Object. Сохранение группы отчётов, истории и указателей на последние снимки проходит в одной транзакции. Повтор семантически идентичной выгрузки сохраняет один снимок. При сбое остаётся предыдущая полная группа отчётов.
- Cloudflare Analytics проверяется до выделения браузера. Транзакция резервирует 90 с под один запуск, включая обработку неопределённости. Для подтверждённого закрытия резерв уменьшается до наблюдаемой верхней границы времени сессии. Остаток консервативен, поскольку Cloudflare может позднее учесть те же сессии. При неполной телеметрии, активной сессии или недостатке времени браузер не выделяется.
- Суточная граница 480 с считается по UTC. Рабочие команды получают до 33 с, технический предел сессии 60 с, keep-alive 10 с. Для известной сессии отправляется явный `DELETE`; закрытие подтверждается Cloudflare. При неизвестном исходе выделения или закрытия автомат останавливается. Все новые задания используют общую группу GitHub Actions для браузерных задач этого репозитория.
- Диагностика содержит предопределённый код стадии, время и признак закрытия. Cookies и Local Storage восстанавливаются только в памяти процесса. XLSX передаётся импортёру по stdin; в базе сохраняются только проверенные агрегаты по каналу и периоду.

## Контролируемая проверка

На ветке разработки workflow проверяет архив, сценарии отказов, уведомление с имитацией Telegram и настоящий Chromium на локальном синтетическом XLSX-ответе. Ручной режим `quota` дополнительно проверяет рабочий счётчик Cloudflare без выделения браузера. Реальный вход, приёмка фактических выгрузок и доставка живого уведомления проходят после развёртывания и входа владельца.
