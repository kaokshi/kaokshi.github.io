# Передача редакционных материалов в ChatGPT через существующий GitHub

## Что уже подключено

ChatGPT имеет доступ через GitHub-коннектор к закрытому репозиторию
`kaokshi/zen-editorial-review`. Отдельно подключать Google Drive или
публиковать материалы в публичном репозитории **не нужно**.

Для изолированных тестов `editorial-production.yml` в приватную задачу
`kaokshi/zen-editorial-review/issues/1` отправляется только отчёт:
`science-01`, `legends-01`, `cinema-01`, стадия задания, безопасный
машинный код остановки и число вызовов модели. Публикации, исходные тексты,
фотографии, изображения, URL первичных источников, ответы модели,
ключи и токены **в отчёт не входят**. Перед отправкой GitHub Actions
проверяет, что репозиторий именно приватный и имя совпадает.

Обновление отчёта ещё **не означает** автоматическую отправку сообщения
в текущую переписку ChatGPT: она становится доступна для чтения ChatGPT
через GitHub, когда пользователь запрашивает результат или срабатывает
отдельная ChatGPT-автоматизация.

## Как безопасно выдать ChatGPT доступ к САМИМ статьям сейчас

Для полной передачи без раскрытия ключей используйте локальную расшифровку
на компьютере владельца и прикрепите готовые файлы в чат.

1. Откройте нужный успешный GitHub Actions `editorial-production` или
   специальный тест с зашифрованным комплектом. Скачайте артефакт
   `editorial-review-*.zip` / `editorial-three-agent-only-*.zip`.
   Распакуйте **только на своём компьютере**; внутри должен находиться
   `owner-review.enc`. Если файл отсутствует, значит комплект не был
   подготовлен; не создавайте его вручную.
2. Получите `owner_private_key.pem`, который ранее генерировали
   **на своём компьютере**. Не загружайте этот файл в чат, GitHub Issues,
   Actions Secrets, публичные репозитории или подключённые приложения.
3. Установите `cryptography` и, из рабочей копии репозитория проекта,
   выполните (пути подставляются локально):

   ```powershell
   py -m pip install cryptography
   py -m src.editorial_delivery retrieve --date 2026-11-23 --allow-incomplete --artifact "C:\PATH\owner-review.enc" --private-key "C:\PATH\owner_private_key.pem" --output "C:\PATH\ZenReview"
   ```

   Используйте дату из комплекта и новую выходную папку, которая ещё не
   существует; это **пример** для теста от 23.11.2026.

4. Проверьте содержимое и отправьте в ChatGPT файлы DOCX, HTML, изображения,
   манифест SHA-256 и статус через прикрепление файла. ChatGPT сможет
   проанализировать и передать владельцу **фактический материал агента**,
   но не вправе переписывать или генерировать его за редакцию.

## Полностью автоматический доступ к открытому содержимому

Чтобы ChatGPT через GitHub прочитал сами статьи **без ручной загрузки**,
понадобится отдельное, явно одобренное владельцем разрешение на
**незашифрованные черновики в приватном GitHub**. Это существенно меняет
нынешнюю модель безопасности: GitHub и подключённые к нему приложения
смогут читать черновики и изображения. По умолчанию такой режим **ЗАПРЕЩЁН**,
ключ X25519 и AES никому не передаётся, зашифрованный архив остаётся
единственным автоматическим хранилищем полного комплекта.

До отдельного подтверждения владельца нельзя включать plaintext-экспорт,
создавать доступные по публичной ссылке статьи, смешивать публичный сайт с
черновиками или ослаблять правообладательские проверки.

## Состояние производства

Автоматическая публикация остаётся отключённой:
`publication_enabled=false`, `schedule.enabled=false`. Канал cinema
допустим только в изолированном тесте; все сообщения статуса в Issue
служебные и не являются разрешением на публикацию.
