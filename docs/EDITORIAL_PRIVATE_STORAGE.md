# Приватные рабочие каталоги редакции

Рабочий каталог содержит тексты, SQLite, журнал этапов и дерево content/assets. Храните его на постоянном диске под отдельной учётной записью с правами каталога 0700 и umask 077. Код публичного сайта должен находиться в другом дереве. У всех запусков одного экземпляра редакции должен быть один рабочий каталог. Для аварийного восстановления выбран restic. Он шифрует содержимое и имена файлов и позволяет восстановить предыдущий снимок. Проверенная версия — 0.18.0.

## Подключение постоянного хранилища

1. На подконтрольном редакции сервере или NAS создайте отдельный закрытый каталог для restic. Предоставьте отдельной SSH-учётной записи доступ по ключу только к резервному хранилищу. Проверьте SSH fingerprint сервера по независимому каналу. Отдельно сохраните пароль restic в менеджере паролей владельца. Потеря одновременно пароля и всех резервных копий ключей делает восстановление невозможным.
2. Установите restic и SSH на доверенной рабочей машине. Настройте алиас SSH `zen-vault` с выделенным ключом, проверенным known_hosts и StrictHostKeyChecking yes. Задайте `RESTIC_REPOSITORY=sftp:zen-vault:/srv/restic/zen` и `RESTIC_PASSWORD_FILE` с абсолютным путём к файлу режима 0600. На новом пустом хранилище однократно выполните `restic init`. Используйте отдельный репозиторий снимков для одного рабочего каталога.
3. Запускайте существующий приватный процесс с постоянным каталогом. После завершения вызывайте команды ниже. Снимок ждёт завершения пишущих процессов конвейера. Другие утилиты, которые записывают данные вне конвейера, следует завершить перед снимком. Каталог моделей и ключи держите отдельно.
4. Для GitHub Actions используйте только доверенный runner и защищённое GitHub Environment. В Secret поместите SSH-ключ и пароль restic, а проверенную запись known_hosts — в конфигурацию окружения. Передавайте их через временные файлы 0600. Выдавайте доступ только заданию доверенной ветки. Не выдавайте секреты коду из PR, не загружайте рабочий каталог в Actions artifacts или cache. Если runner временный, восстанавливайте последний снимок в пустой каталог до запуска. Чтобы два runner не перезаписали историю одного дня, используйте одну группу concurrency для всего цикла восстановления, работы и резервирования, с cancel-in-progress false. Новый workflow и расписание этим изменением не устанавливаются.
5. На другом хосте проверьте `restic check --read-data` и восстановление выбранного снимка. Периодически повторяйте проверку. Сохраните отдельную копию ключа у владельца. Локальное хранилище на той же машине покрывает перезапуск процесса, но потерю машины переживёт только независимая копия.

```bash
umask 077
python src/editorial_daily.py --output /srv/zen/work
python src/editorial_storage.py backup /srv/zen/work
restic snapshots --tag newsroom
restic check --read-data
python src/editorial_storage.py restore /srv/zen/recovery --snapshot latest
```

Для планировщика сохраняйте код завершения редакции отдельно. Снимок нужен и при остановке на проверке или недоступности сервиса. Локальное испытание охватило два реальных досье, SQLite, 14 файлов иллюстраций, HTML и DOCX. Восстановлено и сверено 50 файлов. Независимый SFTP-сервер и доступ runner к нему требуют реквизитов владельца.

## Эскалация в ChatGPT

При статусе assistant_handoff_pending пакет находится в приватном case.json. В handoff перечислены причины, SHA-256 и редактируемые абзацы. Владелец может передать пакет в разрешённую сессию ChatGPT вручную и сохранить ответ локально. Команда повторного запуска того же дела с `--assistant-response /private/response.json` сверяет поле base_text_sha256 и точный before для каждой адресной правки, затем повторяет проверки. В edits нужны paragraph, before, after, reason. Для отказа передаются decision=no_revision, пустой edits и reason. Отправка пакета, получение ответа и происхождение вручную импортируемого ответа требуют подтверждения оператора.

Подписка ChatGPT и доступ к API имеют отдельный биллинг. Автоматический сетевой транспорт в этом окружении не подключён. До авторизации выбранного транспорта и расходов сохраняется assistant_handoff_pending.
