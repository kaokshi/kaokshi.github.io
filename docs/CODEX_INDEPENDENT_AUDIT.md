## Как продолжить приватную проверку

1. Выделить каталог вне репозитория с доступом только редакционного процесса и владельца. Сохранять вместе статьи, SQLite и скрытые подкаталоги с версиями. Доступ на запись в этот каталог эквивалентен полномочию проверяющего.
2. В model-rights.json записать объект с ключами, равными полным идентификаторам моделей. Каждой записи нужны approved=true, проверивший reviewer, license и source_url условий. Для эталона сохранить .scene-anchors/<SHA>/reference и review.json с тем же sha256, reviewer, rights_basis и upload_to_cloudflare=true.
3. Владелец аккаунта проверяет фактический Workers Free и остаток квоты в Dashboard. Локальный запуск требует ZEN_CLOUDFLARE_FREE_PLAN_CONFIRMED=true, сегодняшнюю ZEN_CF_BUDGET_DATE в UTC, ZEN_CF_MAX_REQUESTS от 1 до 32 и абсолютный ZEN_CF_LEDGER в постоянном приватном каталоге. Каждый сетевой запрос моделей делит этот лимит с остальными моделями. В ручном GitHub запуске лимит задаётся входом request_limit. Восемь разных ручных запусков не имеют общего runner-диска. До подтверждения остатка запускать их нельзя.
4. После просмотра оригинала указать в записи плана edit_original_sha256, scene_contract и конкретный fix. При желании добавить style_reference_sha256. После проверки геометрии и опционального Qwen открыть original и candidate из пути в статусе pending. Записать в review.json reviewer_kind=human, reviewer, original_sha256, edited_sha256, scene_contract_sha256, decision=approve или reject. Для approve явно выставить в true шесть проверок из editorial_cloudflare_vision.REQUIRED. Повторно выполнить тот же приватный процесс. Одобрение распространяется только на этот вариант для черновика.
5. Для схемы сохранить illustration.png и review.json в .science-reviews/<specification_sha256> из сообщения pending. Обязательны sha256 файла, specification_sha256, approved, reviewer, artist, license, license_url, source, scientific_source и scientific_basis. Проверяющий сверяет изображённый механизм и подписи с первичным источником. Чтение надписей моделью не заменяет эту сверку.
6. Для проверки Qwen до инференса зафиксировать SHA файла независимых меток человека. Хранить раздельно метки и предсказания по case_sha256, указывать source_group и defect_type, исключить источники разработки, включить положительный и негативный контроль для каждого типа. Запустить python src/editorial_vision_holdout.py LABELS PREDICTIONS TRAINING_SOURCES LABELS_SHA256. Реальный размеченный holdout ещё нужен. Автоодобрение отключено при любом результате этого инструмента.

Порядок продолжения: права и квота, затем один ограниченный тест Schnell/Klein/Qwen на новом рассказе с человеком, затем две новые приватные статьи с полной проверкой источников, обложек, прав и доставки. После отдельного официального решения о запуске применяется существующий маршрут выпуска. До этого момента готовность к ежедневному автономному выпуску не подтверждена.
