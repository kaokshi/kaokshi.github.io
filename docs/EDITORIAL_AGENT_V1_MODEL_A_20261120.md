# Дзен — ИИ-редакция: агент v1 и модель A (решение владельца 20.11.2026)

## Состав моделей
ruBERT v4 исключён из **новой экспериментальной цепочки**. `ModernBERT + LightGBM + AIW-RU BERT (CLI transformer)` → средний **диагностический индекс** (0–100); `AI Accent Detector` — отдельный стилевой сигнал. Это **не процент ИИ-авторства** и не ZeroGPT.

**Правило владельца:** только индекс **строго >80** направляет материал на редакционный осмотр и, при наличии конкретных подтверждённых недостатков, в процедуру доработки. Ровно 80 — не превышение. При ошибке модели или устаревшем отчёте — не объявлять проверку пройденной.

## Будущие роли редакционного ИИ-агента

1. **Главный редактор-оркестратор** — очередь, жанры, дедлайны, остановка неудачных циклов.
2. **Аналитик тем** — актуальные темы и оригинальные идеи, поиск повторов, кино пока на паузе.
3. **Автор** — оригинальный, естественный русский, смысловые блоки, >=3000 символов без пробелов и авторский CTA.
4. **Фактчекер** — первоисточники науки/кино, даты и факты; для мистики оригинальность и непротиворечивость.
5. **Иллюстратор / редактор прав** — 7–8 подходящих изображений, лицензии, ссылки и права; без заглушек и повторов.
6. **Корректор** — логика, дубли, канцеляризмы, LanguageTool/Vale, естественность русского.
7. **Модельный диагност** — четыре реальные локальные проверки, вычисление индекса A и детальные отчёты, хеш текста.
8. **Редактор доработок** — конкретные подтверждённые проблемы → максимум **две** реальные правки с полным повтором проверок.
9. **Эскалация в ChatGPT** — после двух **неудачных** попыток агентов ровно одна содержательная редактура и новая проверка; затем, если неудачно, пересылка владельцу.
10. **Упаковщик и доставщик** — DOCX, изображения и карточки на согласование в 11:00 МСК; до явного запуска только черновики.
11. **RSS / аналитика** — существующий GitHub Pages + RSS, включать только после отдельной команды владельца, позже анализировать просмотры и эффективность.

## Ограничения первой версии

- Автономная генерация полного черновика остаётся отдельным этапом. Для готового черновика предусмотрен исполняемый цикл адресной правки, описанный ниже.
- Нет GitHub→ChatGPT handoff транспорта и подтверждения доставки пользователю. Нельзя выдавать `transport_status:not_connected` за доставку.
- Ранее согласованные ежедневные задачи 08:00/11:00 не переписаны под новую модель, пока не завершены тесты и интеграция. Следует привести их в соответствие после внедрения в `main`.
- Маршрутизатор модели A и политика самообучения вошли в `main` через PR #21 и #22.
- Данные 11 наших статей и ZeroGPT не подтверждают надёжность порога 80. Это добровольный редакционный триггер, не валидированная вероятность.
- Не отправлять текст в сторонние API. Не пытаться оптимизировать содержание ради обмана ИИ-детекторов.

## Передача между этапами

Для каждого материала: immutable SHA-256 очищенного текста, статусы тестов, ссылки на реальные отчёты, список конкретных замечаний, счётчик попыток и полный журнал того, что действительно менялось. Пустая редакция или старый отчёт не засчитываются. Без подтверждённой полноты проверок статья направляется на разбор, не в публикацию.

## Самообучение агента: принятое требование владельца 20.11.2026

Конфигурация `config/agent_learning.json` и правила для Codex в корневом `AGENTS.md` определяют источники обучения. Используются подтверждённые замечания владельца, результаты исправлений и локальных проверок. Показатели Дзена относятся к будущему этапу после официального запуска.

Первая версия самообучения: накопление структурированных случаев → анализ повторяющихся ошибок по жанрам → **предложение** улучшений правил/промптов/моделей в отдельной ветке → независимая проверка без утечек обучающей выборки → одобрение владельца → возможное внедрение с откатом. Не обучаться на непроверенных текстах и не объявлять ZeroGPT эталоном истинного происхождения.

### Запуск редакционного цикла

На Linux-раннере GitHub с моделями из `requirements-editorial.txt`, инструментами из `requirements-quality.txt`, Java 21, Vale и Lychee выполните команду для JSON-черновика `legends` или `science`. Укажите отдельный каталог вне рабочего дерева. Храните этот каталог в приватном контуре.

```bash
python src/editorial_revision.py --article "$DRAFT" --case-dir "$CASE_DIR"
```

`case.json` содержит оригинал, версии, SHA-256, причины правок и отчёты по каждой версии. Два встроенных правила устраняют соседние дословные дубли обычных абзацев и двойные запятые между словами. Удаление целого абзаца проверяет минимальный объём. Модель A запускает дополнительный разбор при индексе строго больше 80. Подтверждённые ошибки исправляются независимо от изменения индекса. При `checks_pending` повторите запуск с тем же исходным файлом и каталогом, чтобы перепроверить последнюю версию.

Для каждой версии выполняются четыре детектора, LanguageTool, Vale, проверка ссылок Lychee, проверка объёма, внутреннего сходства и иллюстраций. Проверка фактов по первоисточникам, оригинальности сюжета, CTA и лицензий требует редакционного подтверждения. Результаты этих проверок перечисляются как ожидающие подтверждения. Отчёт о доступности ссылки подтверждает только её доступность.

### Передача ChatGPT и владельцу

При `assistant_handoff_pending` пакет включает историю, отчёты, открытые вопросы и нумерованные абзацы, доступные для правки. Оператор переносит пакет в согласованный контур ChatGPT и проверяет ответ. Автоматическая доставка требует отдельно согласованной интеграции. Ответ содержит `base_text_sha256` текущей версии и массив `edits`. Для каждой правки нужны номер `paragraph`, точный исходный текст `before`, новый текст `after` и обоснование `reason`. Если правка не требуется, предусмотрен ответ с `decision: "no_revision"`, текущим SHA-256 и объяснением `reason`.

```bash
python src/editorial_revision.py --article "$DRAFT" --case-dir "$CASE_DIR" \
  --assistant-response "$RESPONSE_JSON"
```

После содержательной правки ассистента цикл заново проверяет её и формирует пакет `owner_review_pending`. Он включает оставшиеся замечания и все версии. `transport_status: "not_connected"` означает, что пакет готов к передаче оператором. Если местные правила не дают содержательной правки, пакет может перейти к ассистенту раньше, чем будут использованы обе попытки.

### Сбор подтверждённых замечаний

Владелец сохраняет подтверждённые замечания в отдельном JSON. Поля `reviewer: "owner"`, `slug`, `channel`, `source_text_sha256` и `reviewed_text_sha256` связывают отзыв с конкретной версией. В объекте `findings` укажите категории `facts`, `sources`, `language`, `repetition`, `story_logic` или `image_rights` и итог `resolved`, `unresolved` или `regression`. Оператор выбирает файлы, полученные от владельца.

```bash
python src/editorial_learning.py --review "$CASE_DIR/case.json" "$OWNER_FEEDBACK" \
  --review "$SECOND_CASE" "$SECOND_FEEDBACK" --on-request
```

Отчёт содержит технические ссылки на версии, категории и результаты разбора. Повторяющиеся случаи дают предложения после 20 разных статей одного жанра или по запросу. Для внедрения предложения требуются отдельная ветка, независимая выборка, регрессионные тесты, план отката и решение владельца.

Для единого запуска автора, смысловой редакции и фактчекинга используйте [новый производственный цикл](EDITORIAL_PIPELINE.md).
