# Производство материалов для согласования

Единая точка входа — `python -m src.editorial_brain`. Команды `daily`, `retry`, `review`, `status`, `audit`, `learn` и `health` используют одну редакционную политику. `health` показывает конфигурацию и наличие локальных инструментов без вызовов моделей. `config/editorial_production.json` задаёт объём ежедневного комплекта, сроки и лимиты. Политика публикации и RSS управляются существующим проектом отдельно. В этом контуре действует `publication_enabled=false`.

## Цикл

Оркестратор анализирует архив и поручает текстовые задания только Groq GPT-OSS 120B. OpenRouter удалён из рабочего маршрута, резервный переход на другую модель отключён. Независимый редактор Gemini 3.5 Flash-Lite теперь предусмотрен в коде, но до подтверждения бесплатного проекта и его текущих RPM/TPM/RPD генерация заблокирована: каждый пакет получает конкретный `independent_edit_unavailable: gemini_limits_not_verified` и не считается полностью готовым. Изображения создаёт Cloudflare Klein только в подтверждённом бесплатном режиме. Перед полным циклом требуется безопасный оценочный остаток Workers AI не менее 6000 нейронов; аналитика может запаздывать. Gemini пока служит исключительно для безопасной проверки доступности моделей, без вызовов генерации и без утверждений о точном остатке квоты. Ошибки квот и HTTP 429 останавливают запросы, расходы и автопубликация запрещены.

В 08:00 МСК начинается подготовка для `legends` и `science`. К 10:48 новые этапы производства останавливаются с запасом на упаковку. В 11:00 МСК отдельная задача этого же workflow проверяет комплект и доступность транспорта. UTC-выражения — `0 5 * * *` и `0 8 * * *`. Очередь GitHub может задержать старт. При работе с ограниченным временем пакет и отчёт содержат фактически полученные результаты.

Каналы готовятся параллельно. У каждого задания есть исполнитель, входной SHA-256, история статусов, лимиты и ссылка на результат. Версии сохраняются по SHA-256 канонического текста. HTML и DOCX проверяются повторным чтением, включая хеши встроенных изображений. ModernBERT, LightGBM, Transformer, AI Accent Detector и локальный LanguageTool работают на каноническом тексте. Model A строго выше 80 направляет внимание редактора на материал. Ошибка проверки обозначается как `unavailable`.

Лимит исправлений — пять адресных попыток агента и до двух попыток ChatGPT. Изменённые версии проходят новый QA. Ухудшения остаются в истории и не выбираются для пакета. Пока отдельный транспорт исправлений ChatGPT недоступен, после исчерпания агентного этапа сохраняется `assistant_handoff_pending`. Для владельца формируется отчёт обо всех оставшихся блокировках.

Klein готовит отдельную сцену для каждого задания мистического канала. В научпопе план требует сочетания фотографий и ИИ-визуализаций со свободной пропорцией. Поиск охватывает Wikimedia Commons и NASA. Источники и лицензии записываются в отчёт, включая лицензию на фото и сведения об атрибуции. ИИ-визуализации имеют явную отметку. Применяются SHA-256, перцептивные хеши и локальная оценка соответствия сцены. Обложка ранжируется по соответствию теме, сцене и характеристикам изображения. Автоматическая семантическая оценка служит предварительной проверкой. Неподтверждённые права дают `rights_review_pending`.

## Кино

`cinema` подключён к тому же оркестратору с количеством 0 в ежедневной конфигурации и статусом паузы в редакционной политике. Модуль сверяет год, оригинальное название, идентификатор, режиссёра и актёров по Wikidata и ищет независимое подтверждение. Поддерживаются пересказ, обзор, рецензия и разбор сюжета. При недостатке источников для подробного пересказа план понижается до обзора без спойлеров либо блокируется. Для развёрнутого пересказа нужны два проверенных источника с полным сюжетом.

Кадры берутся из подтверждённых материалов правообладателя. В `config/editorial_cinema.json` источники группируются по Wikidata QID. Запись кадра требует года, оригинального названия, SHA-256, источника, правообладателя, правового основания и ссылки на подтверждение. По умолчанию реестр кадров пуст. Старые материалы и кино-RSS продолжают действовать по прежней политике проекта.

## Защищённое хранение и выдача

По умолчанию Actions обрабатывает файлы во временной директории. Перед сохранением пакет владельца шифруется ключом X25519 с HKDF и AES-256-GCM. В публичный Actions попадают только `checkpoint.enc` и `owner-review.enc`. Контрольные точки Runner можно автоматически восстанавливать с отдельным 32-байтовым ключом AES-GCM из GitHub Secrets `EDITORIAL_STATE_KEY_HEX`. При наличии только открытого ключа X25519 контрольная точка остаётся доступной для восстановления владельцем в авторизованной среде. Автоматическое восстановление в таком режиме имеет статус `storage_configuration_pending`.

Постоянное хранилище указывается в `schedule.private_repository`. Доступ Runner предоставляется через секрет `EDITORIAL_PRIVATE_TOKEN`. Минимально нужны `Contents: Read and write` для выбранного приватного репозитория, `Issues: Read and write` для уведомлений и стандартный доступ к метаданным. В основном репозитории нужны два секрета `EDITORIAL_PRIVATE_TOKEN` и `EDITORIAL_STATE_KEY_HEX`. Для получения владельцем достаточно чтения содержимого приватного репозитория через авторизованный GitHub и локального закрытого ключа. Перед переносом сверяется приватность целевого репозитория. Сохраняются только зашифрованные контрольные точки и пакеты. Для восстановления в Actions используется отдельный ключ `EDITORIAL_STATE_KEY_HEX`. Владелец получает ссылку на защищённый пакет через приватное GitHub Issue. Создание уведомления и подтверждение чтения отражаются отдельно.

Подтверждение бесплатных аккаунтов Groq и Klein хранится в `schedule.groq_free_only` и `schedule.klein_free_only`. Ключи провайдеров хранятся только в GitHub Secrets. Неконфиденциальный открытый ключ владельца задаётся в `schedule.owner_public_key`. Закрытый ключ остаётся в подтверждённой локальной среде, доступной владельцу. До проверки полного маршрута доступ имеет статус `delivery_integration_pending`.

Из авторизованной среды с рабочим GitHub-доступом клиент выдачи скачивает последний полный пакет либо пакет за выбранный день, проверяет источник артефакта, расшифровывает файлы X25519 и проверяет манифесты SHA-256 до записи в указанную директорию. Пример команды для запроса «Пришли статьи на проверку»:

```bash
python -m src.editorial_delivery retrieve --today \
  --private-key /secure/owner-x25519.pem \
  --output /private/zen-review
```

В авторизованной среде путь к ключу может задаваться через `EDITORIAL_OWNER_KEY_FILE`. Подключённый GitHub в ChatGPT предоставляет скачивание зашифрованного Actions-артефакта. Если прямой GitHub CLI недоступен, передайте извлечённый `owner-review.enc` клиенту через `--artifact`. После расшифровки и проверки файлов в авторизованной среде доступны DOCX, HTML и изображения. Автоматическая выдача прямо в ChatGPT требует проверки этого подключения и доступности файлов для владельца.

## Обучение и запуск

Модуль `learn` сравнивает утверждённые владельцем случаи развития и независимой оценки из приватной директории `feedback`. Для случаев независимой оценки поля `baseline_file` и `candidate_file` указывают на сохранённые Markdown-версии внутри редакционного хранилища. Клиент сверяет их канонические SHA-256 и повторно вычисляет измеримые структурные дефекты. Фактчекинг опирается на подтверждённую редактором оценку. Предложение требует повторяющегося дефекта. Дубликаты и пересечение контрольных случаев исключаются по идентификаторам и SHA-256. При ухудшении на контрольной выборке предложение отклоняется. Рабочие промпты и веса требуют отдельного одобрения. Если настроен секрет `EDITORIAL_LEARNING_PR_TOKEN`, команда `learn` может создать черновой PR с агрегированными результатами и предложенной инструкцией. В PR передаются только сводные метрики.

Ежедневное выполнение управляется полем `schedule.enabled` в `config/editorial_production.json`. Текущая настройка — `false`. Для включения владелец утверждает изменение через PR, указывает номер успешного изолированного сквозного прогона, подтверждает доступ к материалам и отключение прежних задач ChatGPT в 08:00 и 11:00 МСК. Workflow сверяет статус указанного прогона и его шаги записи зашифрованных артефактов. Кино остаётся с количеством 0. Для запуска настройка должна находиться в `main`. Для ручной изолированной проверки есть параметр `isolated_validation`. Параметр `validation_public_key` принимает только открытый X25519-ключ теста. Параметр `validation_free_accounts_confirmed` передаёт подтверждение владельца для этого запуска.

Интеграция использует протоколы и подтверждённые вызовы из [#59](https://github.com/kaokshi/kaokshi.github.io/pull/59), [#61](https://github.com/kaokshi/kaokshi.github.io/pull/61), [#62](https://github.com/kaokshi/kaokshi.github.io/pull/62), [#63](https://github.com/kaokshi/kaokshi.github.io/pull/63), [#64](https://github.com/kaokshi/kaokshi.github.io/pull/64) и [#65](https://github.com/kaokshi/kaokshi.github.io/pull/65). Исторические прогоны подтверждают работу экспериментальных маршрутов. Новый производственный маршрут требует отдельного сквозного прогона.

## Квота и подтверждение доставки

Команда Actions `quota` по умолчанию только читает сохранённый статус. Маркеры общего лимита содержат только дату UTC и статус. Суточный HTTP 429 блокирует полные прогоны во всех изолированных пространствах до смены даты UTC и проверки. Смена даты открывает возможность одной короткой проверки, а готовность подтверждается успешным ответом Groq на запрос с пределом 128 токенов. Для ручной проверки после восстановления квоты используются `command=quota`, `isolated_validation=true`, `validation_free_accounts_confirmed=true` и `verify_quota=true`. После утверждённой активации расписания эту проверку выполняет производственный workflow.

Для запроса «Пришли сегодняшние статьи на проверку» режим `--today` ищет только московскую дату. Перед выдачей клиент сверяет SHA-256 и комплектность. Сохранение зашифрованного файла и создание уведомления фиксируются отдельно от открытия пакета владельцем. Пока владелец не подтвердил чтение полного комплекта в авторизованной среде, активация остаётся заблокированной.

Workflow `storage-test` без моделей создаёт контрольные DOCX и HTML двух каналов, шифрует их, удаляет исходную рабочую директорию, скачивает и восстанавливает комплект на другом GitHub Runner и проверяет повторное открытие документов и изображений. Это проверка восстановления на контрольном пакете. Полное подтверждение доставки требует настроенного приватного репозитория и проверки владельцем.

Учёт токенов, настройки бюджетов и разбор исторических запусков описаны в [аудите Groq за 22 ноября 2026 года](EDITORIAL_GROQ_AUDIT_2026-11-22.md).

### Единая проверка длины

Обычный диапазон составляет 3 000–6 000 видимых символов без пробелов. Для 6 001–7 000 обязательна конкретная причина в `length_exception_reason`. Центральный агент принимает её как отдельную служебную строку и сохраняет в журнале проверки и манифесте комплекта. Обоснование исключено из отображаемого текста и его SHA-256. Превышение 7 000 и объём ниже 3 000 блокируют полный комплект. Сборка сайта, маршрутизация и выдача используют ту же функцию политики.

Ручная команда Actions `cinema-test` обращается к публичному источнику фильма и проверяет защитный переход к обзору без спойлеров при недостатке сведений о сюжете. Регулярное производство кино остаётся выключенным.

Для полного испытания трёх каналов ручной запуск `daily` или `retry` принимает `isolated_validation=true` и `validate_cinema=true`. Один материал о кино готовится в отдельном зашифрованном пространстве вместе с двумя активными жанрами. Требуются подтверждённая бесплатная квота, открытый X25519-ключ теста и проверенные разрешения на кадры выбранного фильма. Обычное расписание продолжает использовать ноль статей о кино.

## Обновление 23.11.2026 — квоты провайдеров и отключение OpenRouter

- `src.cloudflare_quota.py` и workflow `cloudflare-quota.yml` измеряют приблизительный суточный расход нейронов; `editorial-production.yml` блокирует `daily`/`retry`, если нет безопасного измерения либо осталось менее 6000 нейронов. Конфигурация — `config/editorial_production.json -> cloudflare_quota_guard`. Это не точный биллинговый лимит и не бронирует внешние ресурсы.
- `src/editorial_gemini_quota.py`, `src/editorial_gemini_cloud_usage.py` и workflow `gemini-quota.yml` без генерации проверяют список доступных моделей и необязательные Cloud Monitoring метрики. `src/editorial_gemini_guard.py` контролирует доступ к второму редактору, лимиты и проект; пока необходимые подтверждения не внесены в конфигурацию, Gemini не генерирует. Официального автоматического точного остатка RPM/TPM/RPD через `models:list` нет, так что он записывается как неизвестный. Текущие лимиты проекта владелец проверяет в Google AI Studio. Gemini не выбран автором или независимым редактором, пока не подтверждены бесплатный тариф, конкретная модель и фактические ограничения.
- OpenRouter не вызывается, не используется для резервной маршрутизации и не участвует в проверках цены. Из-за отсутствия независимого второго текстового провайдера материалы получают `partial_review_pending` с указанным блокером. Для возврата к полному производству нужна отдельно одобренная и проверенная независимая модель.
- Конфиденциальные токены не добавлять в документы или публичные репозитории. Старый `OPENROUTER_API_KEY` в GitHub Secrets нужно удалить владельцу через Settings → Secrets and variables → Actions: коннектор GitHub не предоставляет безопасного управления секретами.
