# Получить статьи на проверку в любое время

В редакции предусмотрена команда владельца **«Пришли последние статьи на согласование»**. Без отдельной генерации команда должна находить последний **существующий** результат полного теста. Полные статьи лежат в зашифрованных GitHub Actions артефактах после завершения соответствующего запуска.

## Автономный поиск и локальное получение

С помощью авторизованного GitHub CLI `gh`, закрытого ключа владельца и инструмента:

```bash
gh auth login
python -m pip install "cryptography>=44,<48"
python src/editorial_request_review.py \
  --owner-key /путь/к/zen_editorial_review_private_key.pem \
  --output /путь/к/новой-приватной-папке
```

Команда:
1. Найдёт 100 последних запусков Actions, выберет последний завершённый тест девяти статей с доступным зашифрованным артефактом.
2. Скачает шифротекст, расшифрует **только локально** указанным закрытым X25519 ключом и проверит наличие `MANIFEST.json`.
3. Создаст приватный каталог со всеми действительно сохранёнными текстами в `articles/*/draft.md` и `draft.json`. Ошибки проверок будут в `reports.json` / манифесте, если они были собраны. Не выдаёт недописанные тексты за одобренные.
4. Не создаст новых статей, не изменит файлы GitHub, не включит RSS или публикацию.

## Для работы через ChatGPT

При запросе в чате ассистент сначала проверяет артефакты через подключённый GitHub. Если доступен зашифрованный архив и в текущем сеансе доступен выданный пользователю **закрытый** ключ, ассистент может попытаться получить и расшифровать настоящий архив, затем отправить полные статьи владельцу на согласование. Если артефактов ещё нет либо ключ недоступен, ассистент обязан прямо назвать ограничение и попросить загрузить расшифрованные тексты либо закрытый ключ в защищённое окружение с пониманием рисков.

**Обратите внимание:** это не встроенный канал GitHub → произвольный чат, а обработка конкретного запроса пользователя. Полная автоматическая отправка вне текущего диалога требует отдельного авторизованного транспорта.

Подготовленные статьи **не должны** считаться прошедшими фактчекинг или готовыми к публикации только по тому, что есть архив. Подписание/разрешение на RSS остаётся у владельца.
