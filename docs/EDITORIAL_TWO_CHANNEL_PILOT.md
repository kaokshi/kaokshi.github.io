# Сквозной локальный пилот Qwen: два активных канала

Этот сценарий разработан для **реального**, а не имитированного запуска Qwen3-4B-Instruct-2507 через локальный llama.cpp/Ollama. Исходники и досье **не должны попадать в публичные GitHub Actions artifacts**. Веса модели не поставляются с репозиторием.

## Подготовка

1. Установить llama.cpp, скачать выбранную GGUF с проверкой SHA-256 и запустить локальную модель по `docs/EDITORIAL_LOCAL_LLM.md`.
2. Установить на локальном исполнителе редакционные зависимости, языковую проверку, Vale и модель A по инструкциям `docs/EDITORIAL_TOOLCHAIN.md`. Для дополнительных метрик рекомендуется `pip install ruts`.
3. Проверить `GET /health` на `http://127.0.0.1:8093`. Исполнитель не принимает удалённый адрес модели и не должен открывать локальный HTTP-порт для внешней сети.
4. Выделить приватный каталог **вне** репозитория для досье. Темы должны быть новыми, а исследования для научпопа — с достоверными первоисточниками.

## Двухканальный запуск

```bash
export ZEN_LLM_BACKEND=llama.cpp
export ZEN_LLM_MODEL=qwen3-4b-instruct-2507
export ZEN_LLM_URL=http://127.0.0.1:8093
export ZEN_LLM_MODEL_REVISION=2fde00ce69dd4899c70d020845e2638353015bba0fdf161b3eb965f2bca4464e

python src/editorial_two_channel_pilot.py \
  --legends-topic "Дежурный, которому звонят из пустой квартиры" \
  --science-topic "Почему над грозой возникают красные вспышки" \
  --science-query "red sprites above thunderstorm peer reviewed" \
  --workspace "$HOME/.local/share/zen-editorial-private"
```

Чтобы получить статус без модели и **не запускать генерацию**, добавить `--status-only`. Эта команда только читает имеющиеся дела и пишет `two-channel-pilot-status.json`, не называя невыполненные проверки успешными.

При повторении команды ранее сохранённые дела продолжаются с последней устойчиво записанной версии и проверок (логика в `src/editorial_pipeline.py`). Ошибки и прерванные шаги сохраняют явные статусы.

Для научной статьи можно вместо сетевого исследовательского запроса передать заранее проверенный приватный файл `--source-documents /private/path/sources.json` с действительными источниками. Нельзя сочинять первоисточники или передавать секреты в GitHub.

Внутри приватного каталога для каждого канала сохраняются `case.json`, `draft.md`, `reports.json`, `sources.json`, журнал и состояние редакций. Итоговый `two-channel-pilot-status.json` содержит только статусы, версии, хеши и имена каталогов, но не полный текст.

`article_ready_for_owner` означает **только** законченность применимых автоматических проверок и правильный размер текста текущей версии. Незакрытые ручные требования (`manual_checks_pending`), изображения, лицензии, факты и подтверждение владельца всё равно остаются необходимыми. Запрос в ChatGPT со статусом `not_connected` **не считается доставленным**. Публикация и RSS всегда выключены.

## Критерии успеха

- Обе статьи действительно сгенерированы локальной LLM и каждый имеет 3000–6000 символов без пробелов.
- Точные версии SHA-256 покрыты повторно выполненными Model A и редакционными проверками.
- Для науки есть проверяемые первоисточники и полный отчёт по фактическим утверждениям.
- У каждого текста понятный статус, история правок и отчёт о требуемых человеческих действиях.
- Отдельно подтверждены права на 7–8 иллюстраций и передача материалов владельцу на согласование.
- Нет утверждения об автономной готовности, пока весь путь не пройден на двух реальных статьях и последовательно повторён.

**Этот PR добавляет надёжный локальный запускатель и тесты, а не доказывает, что Qwen уже создала две статьи на этой машине.**
