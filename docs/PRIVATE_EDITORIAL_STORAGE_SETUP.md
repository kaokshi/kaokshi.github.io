# Подключение приватного хранилища редакции

Текущее назначение: приватный GitHub-репозиторий `kaokshi/zen-editorial-review`. Он уже создан и инициализирован, но автоматическое производство **не активировано**.

## Что уже безопасно настроено

- В `config/editorial_production.json` указано `schedule.private_repository`.
- `schedule.enabled=false`, `owner_approved=false`, `successful_validation_run=null`; публикация и RSS остаются запрещены.
- Проверка `PrivateGit.verify()` дополнительно требует `visibility=private` до чтения или записи.
- Пакеты и checkpoint шифруются до передачи в хранилище.
- Приватный репозиторий не должен хранить открытые статьи, изображения, ключи или токены.

## Что должен добавить владелец в GitHub (НЕ в чат и НЕ в репозиторий)

Открой **публичный репозиторий редакции → Settings → Secrets and variables → Actions → Repository secrets**:

1. `EDITORIAL_PRIVATE_TOKEN`: fine-grained GitHub PAT, ограниченный **только** `kaokshi/zen-editorial-review`, с доступом `Contents: Read and write`, `Issues: Read and write` (для приватных уведомлений) и стандартным `Metadata: Read`. Не давай токену доступ ко всем репозиториям.
2. `EDITORIAL_STATE_KEY_HEX`: криптографически случайный 32-байтовый ключ AES-256, записанный как 64 шестнадцатеричных символа; сгенерировать локально, сохранить в защищённом менеджере секретов. Никогда не коммитить и не публиковать.
3. `EDITORIAL_REVIEW_PUBLIC_KEY` НЕ является секретом окружения. В рабочем режиме программа читает публичную X25519 часть из `schedule.owner_public_key`. Соответствующий **приватный** X25519 PEM-ключ должен храниться исключительно у владельца, вне GitHub и ChatGPT. Не вносить приватный ключ в Secrets публичного репозитория, если в этом нет строго обоснованной необходимости.

Для создания пары X25519 и ключа checkpoint можно использовать Python 3 с установленной библиотекой `cryptography` на собственном компьютере. Публичный ключ допустимо внести в конфигурацию лишь после того, как приватный надёжно сохранён. Никогда не отправляй сюда приватный ключ, токен или `EDITORIAL_STATE_KEY_HEX`.

## Обязательные условия перед включением расписания

- Проверить доступ PAT и фактическое `private` у целевого репозитория в изолированной среде.
- Провести тест шифрования, передачи, восстановления и расшифровки владельцем после удаления временного каталога runner.
- Подтвердить, что владелец реально открыл DOCX и HTML с изображениями.
- Подтвердить корректность границ длины, прав на изображения и проверки по всем активным каналам.
- Отдельно согласовать переключение действующих автоматизаций, чтобы не создавать дубликатов.
- Только после явного разрешения владельца обсуждать `schedule.enabled=true` или публикацию. Не включать их в рамках настройки хранилища.

## Что ещё не подтверждено

Подключённый GitHub-аккаунт имеет доступ к пустому приватному репозиторию, но доступ `EDITORIAL_PRIVATE_TOKEN` из GitHub Actions пока не проверен. Автоматическая доставка в текущий ChatGPT-чат остаётся `delivery_integration_pending` до подтверждённого транспортного маршрута. Не объявлять её подключённой на основании факта успешного GitHub-коммита.
