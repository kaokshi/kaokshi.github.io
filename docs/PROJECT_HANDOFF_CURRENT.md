# Дзен — ИИ-редакция: актуальная памятка и передача проекта

**Дата актуализации: 20 ноября 2026.** Этот документ — короткая точка входа в проект для продолжения в новых чатах/запусках. При расхождении старых записей в `docs/` приоритет имеют последние прямые решения владельца, затем текущие файлы конфигурации и доказанные результаты CI. Статус workflow необходимо проверять заново; указанные ниже статусы — снимок на момент составления, не вечные утверждения.

## Цель и существующая инфраструктура

Создать максимально автоматизированную редакцию **ТРЁХ** каналов Яндекс Дзена:
1. `legends` — «Легенды тёмных улиц»: оригинальные мистические истории; **активен для подготовки черновиков**.
2. `science` — «За гранью очевидного»: занимательный, проверяемый научпоп; **активен для подготовки черновиков**.
3. `cinema` — «Кадр за Кадром»: пересказы и обзоры фильмов; **публикация на паузе**, но жанр участвует в исследовательском обучении модели и разовом тесте шести статей.

Уже существует сайт **https://kaokshi.github.io/** в этом репозитории, HTTPS, GitHub Actions и три RSS: `/feeds/cinema.xml`, `/feeds/legends.xml`, `/feeds/science.xml`. **Не предлагать новый сайт**. Сайт — технический промежуточный хостинг для передачи статей в Дзен; рекламы на нём **не** будет. Возможное продвижение каналов и отслеживание рекламной эффективности — отдельный будущий этап.

## Строгий запрет публикации до команды владельца

- **Не публиковать** статьи в RSS/Дзен, не отключать hold, не снимать паузу кино, не включать публикацию и не выдавать успешный GitHub Actions как разрешение владельца.
- На момент записи `config/site.json` содержит **`publication_enabled: false`**. При этом в том же файле остался **`auto_release_enabled: true`**: это техническая настройка, которая **НЕ является** разрешением выпускать контент и требует отдельной проверки при будущей интеграции. Не путать с реальным состоянием публикации.
- `config/ai_revision_policy.json`: `publication_authorized: false`, все `thresholds` равны `null`, статус `awaiting_independent_validation`.
- Черновики и подготовительные отчёты не являются финальной готовностью к выпуску.

## Последние требования к статьям и редакционной воронке

- Живой, естественный русский язык; без штампованных фраз, канцелярита, искусственной воды и механического звучания.
- Не менее **3000 знаков без пробелов**, типично 3500–5000. Оригинальная художественная мистика; научные факты — с проверяемыми первоисточниками; кино — точный сюжет, спойлерность отмечается в зависимости от задания.
- В дальнейшем каждой статье нужен комплект примерно **7–8 уместных уникальных иллюстраций** с прослеживаемым источником и подтверждённым правом использования; подписи только если осмысленны, не загромождать документ.
- В конце — естественный, ненавязчивый призыв подписаться на соответствующий канал.
- Полная цепочка: тема → статья → проверка стиля/грамматики/логики/оригинальности → проверка фактов/источников → изображения/права → четыре штатных ИИ-детектора и жанровая объединённая модель → исправления → повторная полная проверка новой версии/хеша → ZIP/DOCX для согласования → разрешение владельца → только затем отдельное решение о публикации.
- Реальная адресная редактура: **максимум две попытки**, после каждой — пересчёт показателей и повтор проверок. Если ошибки не устранены — передать владельцу версии и отчёты. Не выдавать только технические тесты за проверку авторских прав и всех фактов.

## Четыре ИИ-детектора и новый порог

Разрешённые встроенные инструменты: **ruBERT v4, ModernBERT, LightGBM, AI Accent Detector**. Не подключать ZeroGPT, внешние детекторы или новые API без отдельного решения. Эти четыре оценки разнородны и не образуют «процент авторства» простым средним.

Владелец утвердил новое **условное** правило: после независимого обучения и подтверждения пригодности объединённой модели **жанровый индекс строго >30 по шкале 0–100** направляет на редакторский разбор/возможную доработку. Индекс не означает «30% текста написал ИИ». Не переписывать бессмысленно лишь ради снижения показателя: нужны содержательные исправления, максимум две попытки, затем владелец. Пока обязательная валидация не пройдена, порог сохраняется в конфигурации как **planned**, но **не активируется** и не влияет автоматически на публикацию.

Требования для одобрения: независимые подтверждённые метки и отсутствие пересечений с обучением детекторов, для **каждого** жанра минимум **120 human + 120 AI в holdout**, заранее замороженный порог, верхняя 95%-я доверительная граница ложных тревог ≤5%, нижняя 95%-я граница выявления ИИ ≥60%. Издательская разметка без аудита и малые выборки этого не заменяют. Кино-рецензии не тождественны длинным пересказам.

Реальная логика: `src/editorial_ensemble.py` (`route_revision`), `config/ai_revision_policy.json`, `src/editorial_research_train.py`, `src/editorial_research_v2.py`, `src/editorial_cinema_pairs_augmented.py`. **Самообучение, подсчёт баллов и маршрутизатор ≠ полностью связанный автономный переписчик.** Интеграция настоящих автономных исправлений и уведомлений остаётся отдельной инженерной задачей.

## Состояние моделей на момент записи

- Усиленный эксперимент по **трём** жанрам: workflow `Train expanded three-genre ensemble (research only)`, последний наблюдавшийся запуск **https://github.com/kaokshi/kaokshi.github.io/actions/runs/44722914073**. Обязательно проверять **последний** run при продолжении, не использовать старые отменённые.
- Снимок последнего run: `legends` и `science` **in progress**; `cinema` **failure**, несмотря на то что создано **20 дополнительных кино-пар** с метками происхождения генерации. Ошибка после генерации: `RuntimeError: Four-detector job incomplete` — нужно найти, какой именно из четырёх детекторов вернул ошибку на образце, и исправить/повторить безопасно. Не объявлять обучение кино завершённым.
- Источник кино: 10 публичных размеченных пар + до 20 локально сгенерированных пар на основе исторических кинорецензий; планируются 18 пар на обучение и 12 на holdout, а также отдельная внешняя выборка человеческих отзывов. Проверять реальные результаты, не подменять ими валидацию длинных пересказов.
- Проблемы предыдущих запусков и их фиксы есть в GitHub Actions; не утверждать «готово», пока реально не получены веса, метрики и подтверждённые CI-отчёты для всех жанров.
- **Никаких придуманных или искусственно усреднённых процентов.** Указанные в ранних отчётах индексы применимы только к конкретному хешу текста и конкретной версии модели.
