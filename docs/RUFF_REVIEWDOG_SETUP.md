# Ruff + reviewdog: защита Python-кода редакции

**Дата:** 20.11.2026. **Статус:** новая проверка через Pull Request; установка не означает, что все проверки уже прошли.

## Что добавлено

- `ruff.toml` — проверка Python-кода без автоматического исправления и без массовой переформатировки существующего репозитория.
- `.github/workflows/editorial-ruff-reviewdog.yml` — workflow для PR в `main`, касающихся Python-скриптов, тестов и конфигурации линтера.
- **Ruff** проверяет `src/` и `tests/`, создаёт машинный отчёт `rdjson`, затем **reviewdog** публикует замечания на **изменённых строках** в PR.
- Отдельно запускаются `compileall` и высокодостоверные Python-проверки `E9,F63,F7,F82` с реальным статусом успешности.
- Не запускается автоматическое исправление. При запуске вручную без Pull Request доступны локальные Ruff и синтаксические проверки, reviewdog не пытается написать комментарии без PR.

## Разрешения и безопасность

Workflow использует только `contents: read` и `pull-requests: write`. PR-review-комментарии отправляются штатным `GITHUB_TOKEN`; секреты вручную не добавляются. При PR из форка GitHub может не предоставить права на запись, и комментирование будет ограничено — не переводить workflow на `pull_request_target` с исполнением непроверенного кода.

**Контент и публикация:** не изменять `publication_enabled: false`, RSS, тексты или изображения. Исправление предупреждений Ruff — отдельное редакторское решение, без массовых автоматически принятых переписываний. Workflow для CI-замечаний — не разрешение на выпуск.

## Как проверить

1. Открыть тестовый PR с ветки `ci/ruff-reviewdog-20261120`.
2. Дождаться workflow `Ruff + reviewdog (Python feedback only)`.
3. Проверить `ruff --version`, число замечаний, `compileall` и high-confidence ошибки в логах.
4. Убедиться, что reviewdog не получил ошибок прав доступа; если в PR нет Python-строк с замечаниями, комментариев может не быть — это нормально.
5. После одобрения человеком объединить PR; публикационную конфигурацию не менять.

**Статус PR и CI необходимо перепроверить в GitHub; не считать запуск завершённым только потому, что workflow добавлен.**
