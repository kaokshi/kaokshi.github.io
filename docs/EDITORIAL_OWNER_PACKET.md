# Подготовка материалов владельцу и передача неудач ChatGPT

Продолжение локального редакционного пилота: `src/editorial_owner_packet.py`.

Назначение: собрать **приватный ZIP** из текущего досье, выбранного текста и подтверждающих проверок, чтобы вручную передать его владельцу или через последующее разрешённое подключение ChatGPT. **Сейчас автоматического транспорта ChatGPT и загрузки материалов в диалог нет.**

Пример:

```bash
python src/editorial_owner_packet.py \
  --case-dir "$HOME/.local/share/zen-editorial-private/legends-draft-<16hex>" \
  --output "$HOME/.local/share/zen-review/legends-review.zip"
```

Каталоги входа и выхода должны находиться вне публичного GitHub-репозитория. Упаковщик отвергает отсутствующие отчёты, несогласованные SHA-256, некорректные статусы и публикационно разрешённые статьи. В пакете есть `draft.md`, `case.json`, `reports.json`, `sources.json` (если есть), манифест с SHA-256 каждого вложенного файла и инструкция для ревью. Файлы остаются приватными, архив получает права `0600`.

ВНИМАНИЕ: архив содержит полный текст и историю, поэтому **не прикладывать его к публичному GitHub Actions**, не делать commit, не отправлять в issue/PR. Создание архива никогда не означает отправку владельцу или выполнение редакторской правки ChatGPT.

Текущее правило Model A: **85 — лишь рекомендательный сигнал**, не процент человеческого/машинного авторства и не разрешение к публикации. Сначала исправлять объективные проблемы. По завершении автоматического анализа для пользователя нужны: статью показать полностью, исходники фактов проверить, подтвердить права на фотографии, получить отдельное одобрение.

Не смешивать smoke-тесты и реальное выполнение. Первый полный двухканальный тест настоящей Qwen по состоянию на создание этого файла не подтверждён.
