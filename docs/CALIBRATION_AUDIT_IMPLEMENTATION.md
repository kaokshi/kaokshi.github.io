# Практическая независимая калибровка: безопасный прототип

**20.11.2026.** Реальная валидация по трём жанрам пока НЕ пройдена; этот компонент создаёт проверяемый способ её проводить, а не заменяет сбор данных.

## Что сделано

- `src/editorial_calibration_audit.py`: проверяет, что по каждому тексту есть четыре завершённых детектора, жанровая метка, уникальный SHA256, источник, идентификатор группы, запись о внешнем аудите происхождения и утверждение отсутствия пересечения с обучением базовых детекторов.
- Отбрасывает повторяющиеся тексты, смешанные жанры, неполные данные и группы/источники, пересекающие границу `calibration` / `final_holdout`.
- Для сохранения пользовательского порога **строго >30** выбирает осторожную границу на *только* калибровочных человеческих текстах и отображает сырой индекс на пользовательскую шкалу: `display_index = clamp(30 + raw_index - calibrated_raw_cutoff, 0, 100)`. Это редакционный индекс, не вероятность ИИ-авторства. Такой метод может резко уменьшить чувствительность и не обещает точности: это только начальный воспроизводимый baseline, а не финальный оптимизированный классификатор.
- Создаёт `frozen_digest`, который фиксирует SHA модели, калибровочные индексы, хеши текстов, метки и разбиение. **Криптографический хеш фиксирует файл, но не доказывает истинность человеческой разметки и не является самостоятельным доказательством даты подписания.**
- По умолчанию **не читает итоговый контрольный набор для настройки порога**. Для его отдельной оценки требуется заранее подписанная вне инструмента запись о заморозке и подтверждении независимости происхождения.
- Проверка финального набора требует не менее 120 человеческих и 120 ИИ-текстов, Wilson 95% upper FPR ≤5% и lower TPR ≥60%. Даже если эти численные ворота пройдены, CLI оставляет `threshold_enabled=false`, `release_authorized=false`, `publication_authorized=false`. Лицом, уполномоченным включать процесс, остаётся владелец.
- Никакие чужие тексты не загружаются в GitHub: вход содержит только индексы, хеши и метаданные. **Самостоятельно заявленные флаги аудита не заменяют независимого проверки вручную.**

## Пример схемы входа (фрагмент; не валидный полный набор)

```json
{
  "schema": "genre-calibration-audit-v1",
  "genre": "legends",
  "model_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "observations": [
    {
      "genre": "legends",
      "split": "calibration",
      "label": "human",
      "raw_index_0_100": 24.5,
      "text_sha256": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
      "source_id": "audited-source-001",
      "group_id": "author-or-family-001",
      "provenance_evidence_id": "external-review-record-001",
      "four_detectors_completed": true,
      "provenance_independently_audited": true,
      "independent_of_base_detector_training": true
    }
  ]
}
```

Для запуска с локальным файлом и минимумом калибровочных примеров:

```bash
python src/editorial_calibration_audit.py --input calibration-local.json --output report-local.json
```

После получения внешней заморозки `pre_holdout_freeze.digest` и подтверждений `auditor_approved_before_holdout_access=true`, `independent_data_audit_completed=true` допускается единократная оценка заранее закрытого независимого набора:

```bash
python src/editorial_calibration_audit.py --input final-independent-local.json --output final-report-local.json --evaluate-final
```

**Не загружать закрытый holdout в PR и репозиторий**, не использовать чужие тексты без разрешения. Принятие вручную подписанного сертификата и решение о включении потока пересмотра остаются внешними процедурами; числовой отчёт не равен законной независимой проверке.

## Что остаётся сделать для реальной системы

1. Набрать и проверить жанровые тексты с подтверждённым происхождением, достаточную выборку и репрезентативные генераторы.
2. Получить реальные оценки четырёх детекторов по этим текстам и сохранить хеш/версию модели.
3. Зафиксировать калибровку **до** просмотра контрольного корпуса и независимо проверить разметку.
4. Выполнить оценку на закрытом наборе, затем сделать теневую эксплуатацию 10–30 статей.
5. Отдельно согласовать практическое подключение безопасного маршрутизатора `>30`; **никакой публикации автоматически**.

CI в ветке PR использует **только синтетические данные** и проверяет запреты публикации.
