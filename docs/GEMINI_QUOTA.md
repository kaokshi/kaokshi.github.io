# Проверка Gemini: ключ и квоты

## Что подключено
- `src/editorial_gemini_quota.py`: выполняет **только** `GET https://generativelanguage.googleapis.com/v1beta/models` с заголовком `x-goog-api-key`. Никакого `generateContent` и платных вызовов.
- `.github/workflows/gemini-quota.yml`: ручная диагностика и расписание 09:35 МСК. Готовность модели и наличие ключа отражаются в безопасной сводке.
- `GEMINI_API_KEY`: приватный GitHub Actions secret основного репозитория. Отсутствие ключа возвращает `unavailable`, не имитирует нулевое использование.

## Что не умеет Google Gemini Developer API с одним ключом
Операция `models:list` перечисляет доступные модели, но не сообщает проектный расход, точные оставшиеся RPM/TPM/RPD или тариф. Поэтому любые поля `remaining_requests` имеют значение `null`, и они не означают «полный остаток».

Действующие для **конкретного проекта и модели** лимиты и расход проверяются в [Google AI Studio → Rate Limits](https://aistudio.google.com/) и Usage. Ограничения могут зависеть от тарифного уровня, модели и состояния проекта; глобальные предполагаемые числа в проект не записывать.

## Безопасность
- Gemini не подключён к текстовой генерации и не заменяет редактора до подтверждения модели, бесплатного тарифа и лимитов.
- OpenRouter отключён: при недоступности Groq редакция не переключается на другую модель и не делает платных запросов.
- Cloudflare по-прежнему делает иллюстрации, но перед новым редакционным циклом действует запас нейронов (см. `docs/CLOUDFLARE_QUOTA.md`).
- Нельзя коммитить ключи, копировать их в issue, подставлять токен в URL или выводить ответы API с конфиденциальными данными.

## Для завершения подключения
Добавьте `GEMINI_API_KEY` в **Settings → Secrets and variables → Actions → Repository secrets**. Запустите workflow **Gemini API access and quota visibility (read-only)**. Фактический результат (ключ распознан, число доступных моделей, наличие выбранной модели) будет в GitHub Actions без публикации секретов.

Точный остаток нельзя безопасно рассчитать без подтверждённого источника учёта всех запросов данного проекта. Для будущей автоматической генерации потребуется отдельный журнал резервирования и учёт запросов между workflow плюс API квот/мониторинга там, где он доступен. Не использовать локальные счётчики как официальную квоту.
