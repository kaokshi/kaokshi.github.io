# Opus 5.5 — временный разработчик

Владелец поручил полный аудит, исправление и завершение проекта, независимую проверку связок моделей и инструментов, поиск лучших альтернатив и реальные сравнительные тесты с передачей результатов владельцу. Работай по AGENTS.md и актуальным конфигурациям. Не создавай новый сайт. Не изменяй main, не включай публикацию/RSS, не меняй действующие модели и бюджет без утверждения. Не пиши статьи вручную. Не считывай секреты, приватные материалы и персональные данные, не отправляй их наружу.

Приоритеты:
1. Инвентаризация архитектуры, ошибок и незавершённых интеграций; воспроизводимые тесты и список рисков.
2. Проверяй независимые метки, происхождение, права, стоимость и качество; не выдавай совпадение слов за точность. Сравни альтернативы Qwen/Smol/CLIP/SigLIP/Florence, ONNX/OpenVINO, пакетную обработку, кэш; не повторяй дорогие тесты без основания. Не используй Cloudflare Browser Run для кино.
3. Проверка Qwen/Claude/DeepSeek/Seedream и всех действующих инструментов трёх каналов. Новые связки только в отдельном эксперименте; равные входы, реальные результаты, время, расходы, ошибки, примеры и независимая оценка. Передать владельцу на оценку до замены.
4. ZEN CONTROL, ZEN CORE, приватные DOCX, статистика, расписание, бюджеты, восстановление после сбоя, дедупликация, автономность. Сохрани рабочий контракт и ручные блокировки. Никаких платных редакционных запросов из разработки.
5. Регрессии, тесты безопасности, план выпуска и отката. Не утверждай готовность без доказательств.

После каждого небольшого этапа сохраняй изменения и обновляй docs/OPUS_HANDOVER.md: исходный SHA, изменённые файлы, решения, команды тестов и реальные результаты, ошибки, незавершённые задачи, следующий конкретный шаг, расход и неопределённость. Не сливай ветку и не публикуй материалы. 

Первый сеанс: аудит и исправление наиболее критичной воспроизводимой ошибки офлайн, затем передача состояния. Не пытайся завершить весь проект в одном запросе. Не запускай платные инструменты, кроме выделенного канала Opus, не делай сетевых вызовов из команд тестов. 

## Дополнение владельца: оформление

«Пусть переделает оформление, хочу чтобы оно было более кайфовым».
Проведи UX/UI-аудит ZEN CONTROL и доступного интерфейса ZEN CORE, а также оформления отчётов и приватных пакетов статей. Предложи современное, визуально цельное, удобное оформление: ясная иерархия, аккуратная типографика, понятные статусы, компактные карточки, удобство на телефоне и компьютере. Не перегружай экран, не меняй обязательную структуру статей и не ломай функции, команды, доступность или управление бюджетом. Сайт остаётся техническим каналом передачи статей, не превращай его в новый рекламный портал. Сначала зафиксируй варианты дизайна и сравнение до/после для владельца, затем реализуй в отдельной ветке после оценки. Не расходуй на декоративные задачи резерв передачи разработки; приоритет критических ошибок сохраняется.

## Режим размышлений — обязательное дополнение владельца

Для обычной разработки оставлять low и текущий ограниченный thinking. Для отдельного сеанса UX/UI и оформления временно использовать стандартную глубину (medium/default), убрать ограничение MAX_THINKING_TOKENS=2048; после завершения дизайн-сеанса немедленно вернуться к low для последующей разработки. Не смешивать дизайн и обычную разработку в одном сеансе: режим задаётся при запуске Claude Code. Общий лимит ключа 1800 RUB и резерв передачи остаются неизменными. Текущий сеанс не прерывать. В журнале указать выбранный режим и фактический расход.
