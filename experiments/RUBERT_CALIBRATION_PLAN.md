# ruBERT v4: честная калибровка для редакции (пилот)

**Статус:** исследование, НЕ включено в основную редакцию, НЕ меняет текущий жёсткий порог ruBERT 25% по максимуму окна, НЕ публикует статьи. Используются только существующие GitHub ruBERT v4 и тот же набор остальных трёх интегрированных проверок; новых AI-детекторов и ZeroGPT нет.

## Проблема

Наш текущий `src/rubert_v4_runner.py` разбивает текст на перекрывающиеся окна по 85 слов с шагом 65 слов, чтобы избежать усечения модели. Но для целой статьи показывает `max(window_probabilities)`. Максимум **растёт с количеством окон**, даже если типичная стилистика текста не меняется. Число 60% по одному отрывку нельзя честно называть «вероятностью, что статья написана ИИ». Даже откалиброванное значение модельного классификатора не равно универсальной вероятности или способности предсказать модерацию Яндекс Дзена.

На оригинальной мистической статье «Девятый этаж» при [завершённом запуске GitHub](https://github.com/kaokshi/kaokshi.github.io/actions/runs/44687507196) получены 17 окон и первоначальный максимум 0,6000, хотя собственный классификатор модели показал `human`. Значения других внутренних моделей: ModernBERT 0,05%, LightGBM 5,32%, AI Accent Detector 6,02% (стилистический индекс, не вероятность авторства).

## Улучшенная аналитика

`src/rubert_calibration.py` принимает **реальный JSON отчёта существующего ruBERT** и отдельно показывает:

- максимум `max`: наихудший фрагмент — остаётся неизменным показателем активного 25% шлюза до валидации;
- медиану `p50` и 75-й/90-й процентили `p75/p90`: насколько модель подозрительна в типичных и нескольких верхних окнах, а не только в одном;
- средний балл `mean` и долю окон `share_over_25`: насколько сигнал широко распространён по статье.

**Реальная пилотная статья:**

| Показатель | Значение | Значение для редактора |
| --- | ---: | --- |
| Максимум по 17 окнам | 60,00% | Сильнейший отдельный сигнал, текущий блокирующий порог не пройден |
| Среднее по окнам | 26,14% | Не калибровано как доля ИИ |
| Медиана | 30,38% | Центральное модельное значение |
| 75-й процентиль | 30,38% | Более устойчивый взгляд на повышенные оценки |
| 90-й процентиль | 48,15% | Повышенные оценки нескольких окон |
| Доля окон строго выше 25% | 52,94% | 9 из 17 окон; перекрывающиеся окна НЕ независимы |

Разница между `max` и `p75` на конкретной статье наглядно показывает влияние экстремального окна. Однако пока нет оснований утверждать, что p75 «точнее» на реальных человеческих текстах.

## Как установить честный новый порог

1. Собрать **действительно подтверждённые** обучающие контроли по каждому жанру отдельно: художественные истории, научпоп, позднее кино. Не использовать все собственные статьи как «100% ИИ» или как человеческие тексты без подтверждённого происхождения. Каждая запись должна иметь уникальный ID, достоверный источник и этикетку `human`/`ai`.
2. Учитывать одинаковую длину и сопоставимую редакционную обработку текстов. Включить полностью человеческие статьи, сгенерированные, редактированные человеком и смешанные тексты для дополнительного стресс-теста; помечать их как отдельные категории, а не выдавать спорные за надёжную разметку.
3. Разделить на выборку поиска порога (`calibration`) и независимый контроль (`holdout`) по исходному документу/авторской группе, исключая одинаковые перефразирования между группами. Для начала скрипт требует **не менее 50 каждого достоверного класса** для выбора и **30 каждого класса** для контроля **в каждом жанре**. Этого мало для надёжной гарантии ошибки 5%, но достаточно, чтобы начать оценивать.
4. Исследовать `max`, `p75`, `mean` и долю высоких окон, выбирать порог только по calibration с целевым наблюдаемым **false positive rate ≤5% для человеческих текстов**, затем считать `FPR` и `TPR` на отложенном наборе. Дополнительно до внедрения оценить доверительные интервалы, зависимость от длины, тематик, новых версий генераторов и ошибки на отредактированных текстах.
5. Не путать порог с вероятностью: для утверждения «30% вероятность ИИ» нужен отдельный статистически проверенный вероятностный калибратор с reliability diagram, Brier score, репрезентативной базовой долей ИИ и независимой проверкой. Без него выводить только **неоткалиброванный индекс подозрительности**, с указанием метода.
6. **Не переносить новый порог в автоматический выпуск** только на основании маленького теста. Утверждать смену основного порога после пилота и независимой человеческой оценки; все остальные проверки фактов, лицензий и русского языка остаются обязательными.

Этот протокол не обещает обойти или предсказать автоматическую проверку Дзена и не предназначен для «оптимизации текста под детектор» ценой стиля/достоверности. Главное — не отвергать хорошие тексты из-за одного случайного окна и не пропускать плохие на основании низкого индекса.

## Работа без новых инструментов

```bash
python -m unittest tests.test_rubert_calibration -v
python src/rubert_calibration.py --windows-json experiments/rubert-ninth-floor-window-scores.json
# Для исследовательской выборки с подтверждённой разметкой:
python src/rubert_calibration.py --dataset-jsonl path/to/validated-corpus.jsonl --metric p75
```

Никаких полей одобрения статьи, конфигурации сайта или RSS этот код не изменяет. Исходные тексты не публикуются в экспериментальном отчёте. Для каждого нового образца использовать только реально выполненный GitHub ruBERT.

## 20 ноября — единая оценка всего текста по шкале 0–100

По просьбе владельца реализован дополнительный выход из **той же** модели ruBERT v4: `whole_document_index_percent`. Он покрывает весь текст, а не только максимальное окно. Из-за ограничения входа upstream-модели на 256 токенов физически пропустить большой текст в одном вызове без изменения архитектуры/дообучения нельзя. Вместо этого берём все небольшие перекрывающиеся окна; каждое слово получает среднее из оценок покрывающих его окон, после чего рассчитывается средняя оценка всех слов документа. Это один читаемый показатель 0–100: **чем больше, тем сильнее сигнал ИИ-происхождения у существующей модели**, а не вероятность, что материал создан ИИ.

По [реальным 17 окнам пилота «Девятый этаж»](https://github.com/kaokshi/kaokshi.github.io/actions/runs/44687507196) результат **26,61/100** по всем словам, в сравнении с **60/100** по старому максимальному окну. Новая оценка не сравнивалась с подтверждёнными человеческими/ИИ контрольными корпусами, поэтому называть её «26,61% вероятность ИИ» нельзя. Эта формула не учитывает калибровку модели, пределы ошибок, качество обучения или неизвестную систему Дзена.

Код: `src/rubert_calibration.py:document_coverage_score`, новая запись в `src/rubert_v4_runner.py` и `src/editorial_ai_check.py:threshold_review`; числовой показатель пишется в `whole_document_index_percent`, а поле `probability_ai_generated` остаётся `null`. Текущий блокирующий порог `25%` по максимальному окну **на этой экспериментальной ветке не меняется**. Принятие нового единого порога допустимо лишь после реальной оценки ложных срабатываний на размеченных текстах для каждого жанра. Не добавлять статьи в RSS в рамках эксперимента.
